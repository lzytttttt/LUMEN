# 07 播放与导出 —— 状态机、转场、讲者视图与单文件 HTML

> 本文写 `src/play/**`、`src/export/**` 与 `src/player/entry.tsx` 的实现事实：播放状态机与常量、5 种转场、讲者窗协议、独立 HTML 的组装与体积护栏、播放器内核构建、打印/PDF/PNG/工程文件，以及 `file://` 下的实测结论。
> 渲染侧能力（3D 预算、SVG 动效）见 `doc/05-SVG与3D渲染.md`；数据契约见 `doc/03-数据模型与DSL.md`。

## 1. 模块边界

```
play/                     export/                         player/
playbackCore.ts  ──┐      standalone.ts ──┐               entry.tsx（IIFE 内核）
PlaySurface.tsx  ──┼──▶   printRoute.ts ──┼──▶ PrintPages ◀── StandalonePrint
SlideLayer.tsx   ──┘      threeFrames.tsx ┘     （打印页，两处共用）
Player.tsx / PresenterWindow.tsx        pdf.ts / png.ts / projectFile.ts
```

- `PlaySurface` 是**唯一**的播放画面实现：编辑器播放、独立 HTML 播放器都用它，禁止各自再写一份。
- `PrintPages` 同时被应用内 `PrintHost` 与独立 HTML 的打印模式复用，所以打印产物在两边一致。
- `export/**` 只读 deck：抓 3D 帧、换静态图都在**副本**上做（`prepareDeckForPrint` 返回新 deck）。

## 2. 播放状态机

纯逻辑全在 `playbackCore.ts`（无 React / DOM / 定时器），`usePlayback` 只把它接到 React 与计时器上。

```ts
interface PlaybackState {
  total: number            // 0 = 没有可播内容
  index: number            // 当前幕下标
  direction: 'fwd' | 'back' // 转场方向
  blackout: boolean
  autoplay: boolean
  elapsedMs: number        // 计时读数，由外部按 200ms 推进
}
```

| 常量 / 函数 | 值 / 语义 |
|---|---|
| `AUTOPLAY_MIN_MS` | `250`（幕写了 0ms 也不至于疯狂翻页） |
| `AUTOPLAY_MAX_MS` | `600_000`（与 schema 的 `durationMs` 上限一致） |
| `clampIndex(i, total)` | 夹到 `[0, total−1]`；`total <= 0` 恒为 0 |
| `stepIndex(i, total, ±1, loop)` | 越界返回 `-1`（表示不动）；`loop` 时首尾相接 |
| `autoplayDelayOf(durationMs, fallback)` | 幕自带 `durationMs` 优先，否则全局设置，最后夹到 250ms–600s |
| `formatClock(ms)` | `m:ss`，≥1 小时用 `h:mm:ss` |

动作全集：`syncTotal / go / next / prev / first / last / setBlackout / toggleBlackout / setAutoplay / toggleAutoplay / setElapsed / resetTimer`。

- `next/prev` 在 `total` 变化时会先对齐（`go` 也带 `total` 参数），避免 deck 增删幕后下标越界。
- 循环回第一卷仍记 `direction = 'fwd'`（方向语义连续），后退到最后同理记 `'back'`。

### 2.1 `usePlayback`

| 行为 | 实现 |
|---|---|
| 总幕数同步 | `useEffect([total]) → dispatch('syncTotal')` |
| 计时 | `setInterval(200ms)` 推 `elapsedMs = Date.now() − startedAt`（用时间戳，不累加，避免漂移） |
| 停留时长 | `durationOf(index)` 走 ref 读取（换幕/改设置都不重建定时器），缺省回落到 `autoplayMs`（默认 8000） |
| 自动播放 | 黑屏 / `total ≤ 1` / 到末幕且未开循环 → 不排下一次；到末幕且非循环会**自动关掉 autoplay**，避免"开着却不动" |

## 3. 播放面与转场

`PlaySurface` 的输入只有 `deck / index / playing`，内部按 `min(w/1600, h/900)` 等比缩放（`ResizeObserver` + `--play-ms` 变量）。

- **双层缓冲**：`data-phase="out"` 是正在离场的上一幕，`"in"` 是当前幕；索引变化在 `useLayoutEffect` 里记账（否则会闪一帧新幕），转场结束 `ms + 80` 后卸载离场层。
- **时长归一化**（`planTransition`）：`0` 或 `kind === 'none'` → 0ms；其余夹到 `200–800ms`（幕里写 2000ms 也按 800ms 播）；`prefers-reduced-motion` 统一退化成 `120ms` 淡入。
- 离场层固定 `playing = false`：3D 立刻停转、入场动效不重放。

| 转场 | 实现（`transitions.css`） |
|---|---|
| `fade` | 入场/离场各一个 opacity 关键帧 |
| `push` | `translate3d(±100%, 0, 0)`，`data-dir` 决定从哪边推入 |
| `wipe` | 入场层用 **`clip-path: inset(0 0 0 100% → 0)`** 揭开（从右擦），`back` 时 `inset(0 100% 0 0)`；离场层只做线性淡出 |
| `flip3d` | `rotateY(±90° → 0)` + opacity 0.2→1；舞台容器 `perspective: 2400px` |
| `none` | 不带任何动画，也不挂离场层 |

只动 `transform / opacity / clip-path`，三种属性都在合成层完成，不触发 layout。

## 4. 播放器外壳（`Player.tsx`）

| 常量 | 值 | 作用 |
|---|---|---|
| `CHROME_IDLE_MS` | `2500` | 无操作后收起控制条 |
| `HINT_MS` | `3000` | 首屏操作提示停留时长 |
| `SWIPE_MIN_PX` | `48` | 触摸/鼠标横向滑动翻页阈值（且横向位移 > 纵向 1.4 倍、时长 < 900ms） |

键盘（捕获阶段监听 + `stopPropagation`，避免与 App 的全局 Esc 打架）：

| 键 | 行为 |
|---|---|
| `→` `PageDown` `Space` | 下一幕 |
| `←` `PageUp` | 上一幕 |
| `Home` / `End` | 第一幕 / 最后一幕 |
| `N` / `Shift+N` | 下一幕 / 打开讲者视图 |
| `P` `F` `O` `B` `T` `R` | 上一幕 / 全屏 / 总览 / 黑屏 / 计时显隐 / 计时归零 |
| `?` | 帮助浮层 |
| `Esc` | 先关浮层 → 退出播放（回到编辑器并停在当前幕） |

- 点击左右 35% / 65% 翻页，但**交互块（HTML iframe / `data-interactive` 的 3D / a / button / input）上不触发**；黑屏时任意点击先退出黑屏。
- 进入播放会尝试 `requestFullscreen()`，失败静默（无权限/iframe 受限很常见）；退出播放时把全屏还回去。
- 总览（`Overview`）用 `mode="thumb"` 缩略图（不建 WebGL、不跑动效），一屏 3×3，点哪去哪。

## 5. 讲者视图协议

`presenter.ts` 定义通道与消息，`usePresenterSync` 管主窗侧，`PresenterWindow` 负责开窗与注入。

| 消息 | 方向 | 载荷 |
|---|---|---|
| `hello` | 讲者窗 → 主窗 | 无（请求首帧） |
| `deck` | 主窗 → 讲者窗 | `{ title, slides: [{ name, notes }] }` |
| `state` | 主窗 → 讲者窗 | `{ index, blackout, autoplay, elapsedMs, total }`（计时按**整秒**节流） |
| `command` | 讲者窗 → 主窗 | `{ action: 'next' \| 'prev' \| 'go' \| 'blackout' \| 'timer-reset', index? }` |

- 通道名 `SYNC_CHANNEL = 'lumen-sync'`（BroadcastChannel）；`canBroadcast()` 为 false 时 `open()` 返回 false，主窗 toast `play.presenterBlocked`。
- 讲者窗**不加载 React 应用**：`window.open('', 'lumen-presenter', …)` 后 `document.write()` 注入静态骨架 + 内联 CSS + 一段连接脚本。
- 安全约定：注入的 HTML 里没有任何 deck 内容，标题/备注一律 `textContent`；i18n 文案进脚本前经 `jsonForScript()`（`JSON.stringify` + 把 `<` 转成 `\u003c`），杜绝 `</script>` 注入。
- 主窗在 `deck` 引用变化、`index/blackout/autoplay/整秒` 变化时推消息；`hello` 到达时全量补发一次（避免"打开瞬间状态已发完"的竞态）。
- 窗口生命周期：800ms 轮询检测讲者窗被关；主窗 `beforeunload` 或卸载时关掉讲者窗（反过来不成立）。

## 7. 独立 HTML 的组装

`buildStandaloneHtml(deck, options)` 的组成（`composeStandaloneHtml` 是纯函数）：

| 部分 | 细节 |
|---|---|
| 播放器内核 | `fetch('player/lumen-player.js')` + `.css` 内联；响应像 HTML 文档（开发服回落到 index.html）或为空 → 抛 `export.playerMissing`，**绝不静默产出坏文件** |
| 主题变量 | `themeVarsCss(themeCssVars(theme, deck.themeOverrides))` 写进 `<style id="lumen-theme">` |
| 打印样式 | `PRINT_CSS` 写进 `<style id="lumen-print-css">` |
| deck | `<script type="application/json" id="lumen-deck">`，经 `escapeJsonForScript()`（`< > &` 与 U+2028/9 全部转 `\u` 转义） |
| 素材 | `<script type="application/json" id="lumen-assets">`，`assetId → dataURL` |
| 启动 | 内联 boot 脚本读两个 JSON、判断 `?print=1` / `#print`，调 `window.LumenPlayer.mount(root, deck, { assets, print, title })` |

- 转义三件套：`escapeJsonForScript`（`<`/`>`/`&`/U+2028/9）、`escapeScriptText`（`</script` → `<\/script`）、`escapeStyleText`（`</style`）。
- `prepareStandaloneDeck()`：**默认删掉 `slide.notes`**（不把作者私货带进导出文件），其余字段一个不动；`includeNotes: true` 才保留。
- 文件头带 `data-lumen-standalone="1" data-lumen-slides="N" data-lumen-theme="…"`，方便外部校验与截图定位。
- 文件名 `slugify(title) + '.html'`。

### 7.1 体积护栏

| 常量 | 值 | 行为 |
|---|---|---|
| `STANDALONE_WARN_BYTES` | `12 MB` | 仍产出，附 warning（`export.sizeWarning`） |
| `STANDALONE_ABORT_BYTES` | `24 MB` | 直接抛错（`export.tooLarge`），不产出坏文件 |
| `PLAYER_ASSET_BASE` | `'player/lumen-player'` | 内核产物路径（相对站点根） |

素材缺失只 warning（`export.warnAssetMissing`）；关掉内联素材（`includeAssets: false`）同样 warning（`export.warnAssetsSkipped`）。

## 8. 播放器内核（IIFE）

`vite.player.config.ts` 把 `src/player/entry.tsx` 打成 **IIFE**，全局名 `LumenPlayer`，产物落在 `public/player/`：

| 产物 | 体积（本轮采样） |
|---|---|
| `public/player/lumen-player.js` | **1,154,596 B ≈ 1.10 MiB**（含 three，`inlineDynamicImports`） |
| `public/player/lumen-player.css` | 16,301 B |

- 关键 alias：`@/assets/assetStore` → `src/export/playerAssetBridge.ts`（只影响这份构建）。单文件 HTML 里没有 IndexedDB，图片靠 `window.__LUMEN_ASSETS__`（`assetId → dataURL`）内联表；桥让 `useAssetUrl / getAssetUrl / getAssetDataUrl` **优先查表**，查不到才退回真实资产库。
- 对外契约：`window.LumenPlayer.mount(element, deck, { startAt?, assets?, print?, title? }) → boolean`、`unmount()`；`PLAYER_VERSION = '1.0.0'`。
- 运行环境是 `file://`：不许 service worker、不许 fetch 相对资源、**零外部请求**；键盘、全屏、打印都在内核里自足。
- `mount()` 先用 `deckSchema` 校验，失败把 `invalid deck data` 写进宿主元素并返回 false。
- 打印模式（`?print=1` / `#print` 或 `print: true`）走 `StandalonePrint`：抓 3D 帧 → `PrintPages` → `waitForPrintReady()` → 自动 `startPrint()`。

## 9. 打印 / PDF（`printRoute.ts` + `PrintHost`）

- `PRINT_CSS`：`@page { size: 1600px 900px; margin: 0 }`，`.lumen-print__page` 固定 1600×900 + `break-after: page`，`:last-child` 取消分页；打印时 `body > *:not(.lumen-print-layer)` 一律 `display: none`，并强制 `print-color-adjust: exact`（3D 海报、主题底色不能被省掉）。
- 打印层由 `PrintLayer` **portal 到 body**：分页必须发生在普通文档流里，绝对/固定定位的祖先会打断分页。
- 触发：地址栏 `?print=1` / `#print`（`isPrintRequested`）或应用内 `requestPrint()`；总线挂在 `globalThis.__LUMEN_PRINT_BUS__` 上（HMR 下双实例也不丢请求）。
- `hasPrintHost()` 决定 `exportPdf()` 走哪条路：有宿主 → 就地打印（可 await）；没有 → `buildPrintUrl()` 开新窗口（被拦截时抛 `export.pdfBlocked`）。
- `waitForPrintReady(extraMs = 160)`：等 `document.fonts.ready` → 两帧 rAF → 所有 `img` 的 `load/error/decode`（单图上限 1.5s）→ 再等一小段。
- `startPrint()` 返回两档 Promise：`settled`（`afterprint` 或 **2s 兜底**，给调用方"已发起打印"的信号）与 `closed`（只有 `afterprint` 真正触发，可能永远不来）。
- `PrintHost` 用 `phase: idle → preparing → ready → printing → done` 与 `jobRef` 做"这一次任务"的身份标记（不用 effect 的 alive 标志，因为流程内部 `setPhase` 会让 effect 重跑）；`CLOSE_FALLBACK_MS = 45_000` 兜底收起打印页；就地在打印结束后收起打印页，**路由打印保留**（方便再打一次）。
- 打印前的 3D 处理：`prepareDeckForPrint()` 抓帧换成 `<img>`，失败也不阻断打印（直接用原 deck，3D 幕走渲染层降级）。

### 9.1 3D 抓帧（`threeFrames.tsx`）

| 常量 | 值 | 用途 |
|---|---|---|
| `CAPTURE_ID_PREFIX` | `lumenPrint_` | 抓帧副本的 block id 前缀，**与舞台上的 runtime 键隔离**（否则会抢占并释放编辑器正在跑的 WebGL 上下文） |
| `POSTER_ASSET_PREFIX` | `lumenShot_` | 抓到的帧写进资产库时的 assetId 前缀 |
| `FRAME_TIMEOUT_MS` | `6000` | 单幕等 `data-three-state` 进入 `live/fallback` 的上限 |

流程：逐幕挂一个离屏 `SlideRenderer mode="export"` → 等该幕全部 3D 块进入终态 → `captureThreeFrame(key)` → `putAssetFromDataUrl` 登记 → `threeToImageBlock()`（几何/z/旋转/透明度/圆角全部照抄，`fit: 'cover'`，`alt = "3D · <preset>"`）。一次只挂一幕，绝不并发多份 WebGL 上下文。

## 10. PNG

`exportPng(deck, { slideId?, scale?, scope?, fileName? })`：

- `scale` 默认 **2**，夹在 `1–4`；`scope: 'current'` 只导当前幕（`uiStore.activeSlideId`）。
- 每幕：`prepareSlideForSnapshot()` 抓 3D 帧 → 离屏 `SnapshotStage`（`position: fixed; left: -20000px`）→ 等 `fonts.ready` + 图片解码（`IMAGE_WAIT_MS = 4000`，超时就按现状截图）→ `html-to-image` 的 `toPng(pixelRatio = scale)`。
- **`html` 块是 iframe，跨文档内容无法序列化进 SVG foreignObject → 位图里会是空白**，出现这类块时整体附一条 `export.pngFallback` warning。
- 单幕失败只记 `export.pngSkipped`，不整体失败；下载之间间隔 260ms 降低"批量下载被拦"的概率，疑似被拦再附 `export.pngBlocked`。

## 11. 工程文件

`projectFile.ts`：`buildProjectFile(deck)` → `deckFileSchema.parse({ kind: 'lumen.deck', schemaVersion, exportedAt, deck, assets })`，素材经 `collectAssetIds()`（`image.assetId` + `three.posterAssetId`）收集成 dataURL；下载名 `slugify(title).lumen.json`。
导入侧 `readProjectFileText()` 走 `parseDeckFile()`（允许裸 deck），再把 `assets` 逐条 `putAssetFromDataUrl()` 回填资产库（已存在则跳过）。

## 12. `file://` 实测结论

用 `scripts/probe-*.mjs`（Chrome + `--enable-unsafe-swiftshader`）对导出的 9 幕示例逐项验证，产物落在 `harness/out/export/`：

| 检查 | 结果 |
|---|---|
| 外部网络请求 | **0**（`http(s)://` 请求计数为 0） |
| 首屏 | 封面文案正确渲染 |
| `→` 翻到第 4 幕 | `4 / 9` |
| `End` | `9 / 9` |
| `O` 总览 | 9 个缩略图 |
| `B` 黑屏 | `data-blackout=true` |
| console | `file://` 下无 console error |
| `?print=1` | 9 页；打印视图里 **0 个 `three` 块、2 张静态图**（抓帧成功） |
| `page.pdf()` | 9 页 / 401,890 B |
| 导出体积 | 9 幕示例 **1,204,989 B ≈ 1.15 MiB**（内核 1.15MB 占大头） |
| 素材 | `assetId → dataURL` 内联，`file://` 下渲染成真图，仍零外部请求 |

`tests/e2e/` 把这套流程固化成 10 个用例（`export.spec.ts` 覆盖 `file://` 可播 + 零外部请求，`print.spec.ts` 覆盖 9 页 + 0 canvas + PDF 9 页）。

## 13. 已知限制

- 独立 HTML 的体积下限就是播放器内核（≈1.1 MiB）；素材一多就逼近 12MB 警告线，24MB 直接拒绝导出。
- 内核会把 three 一起打进来（`inlineDynamicImports`），所以"没有 3D 的演示"也背着这份体积；这是"零外部请求"的代价。
- 打印依赖浏览器对话框，`settled` 只是"已发起"，**无法知道用户是否真的保存了 PDF**；`closed` 可能永远不 resolve（有 45s 兜底）。
- PDF 的页数等于幕数，但页面尺寸是 `1600px × 900px`：A4 打印会被缩放，页边距与纸张由浏览器决定。
- PNG 里的 `html` 块是空白的（iframe 不参与 `html-to-image`），只能靠 warning 提醒；3D 幕依赖抓帧，抓帧超时（6s）就退化成静态占位。
- 讲者窗用 `document.write` 注入，属于旧 API：CSP 严格的宿主页面会拦；`BroadcastChannel` 不可用时整个讲者视图不可用（只提示，无降级方案）。
- 自动播放到末幕且未开循环时会自动关闭（避免"开着却不动"），用户可能觉得是 bug。
- 播放态的键盘是捕获阶段监听并 `stopPropagation`，因此播放时编辑器的 `⌘/Ctrl` 组合键之外的快捷键全部让位——这是刻意的，但意味着自定义快捷键在播放态不会生效。
