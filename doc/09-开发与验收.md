# 09 开发与验收 —— 命令、测试分层与 DoD

> 本文是"能不能交付"的操作手册：环境、命令、测试分层与当前真实数字、验收清单、常见故障。
> 所有权与并行开发规则见 `doc/00-工程契约.md`（本文只引用，不重复长文）。

| 截图 harness | `& $node scripts/snapshot.mjs http://127.0.0.1:5273` | 产出 `harness/out/*.png` + `slides/*.png` |

`package.json` 的脚本（`dev`/`build`/`test`/`e2e`/`snapshot`/`typecheck`）与上表一一对应；`predev` 与 `prebuild` 都会先执行 `scripts/build-player.mjs`。CI 用 Node 22 + pnpm 11，并跑 `pnpm install --frozen-lockfile`；本地若用 bundled pnpm，同样以 lockfile v9 为准。

### 2.1 端口与进程约定

| 端口 | 用途 | 约定 |
|---|---|---|
| 5273 | 开发 / 预览 | `strictPort: true` + `host: 127.0.0.1`；**同一时刻只允许一个**，已存在就复用 |
| 5274 | e2e 专用 | `playwright.config.ts` 的 `webServer` 会拉起 `scripts/dev-server.mjs 5274`，`reuseExistingServer: true` |

### 2.2 首次上手顺序

1. `& $node scripts/build-player.mjs`——先有播放器内核，否则导出独立性验证无从谈起。
2. `& $node scripts/dev-server.mjs 5273`——开发服起来后打开 `http://127.0.0.1:5273`，3 秒内应看到 9 幕示例。
3. `& $node node_modules/vitest/vitest.mjs run`——改动前先确认基线是绿的。
4. 改完跑 `tsc --noEmit` + `vitest run`，再 `vite build`。
5. 需要视觉确认时跑 `scripts/snapshot.mjs`，看 `harness/out/console-errors.json` 是否为空。

## 3. 所有权与并行

- 写入域按模块划分（`doc/00-工程契约.md` §2）：跨域需求（新 store action、新 primitive、新 i18n 命名空间、新依赖）先找 Lead，不要自己动别人的目录。
- 共享文件（`src/i18n/messages/editor.{zh,en}.ts`）只允许 `edit` 局部插入，禁止整文件覆盖；写入冲突报 `FS_STALE_VERSION` 时重新 read 再 rebase。
- 测试例外：可以为自己模块**新增** `tests/unit/<area>.test.ts`，不要改已有测试文件。
- 同一份文件不要被两个模块同时改；`src/schema/**`、`src/state/**`、`src/themes/**` 属 Lead，改动要先对齐字段契约。

### 4.2 jsdom 的补齐（`tests/setup.ts`）

测试环境只补三类浏览器 API，新增缺口请加在这一处，而不是在各自的用例里各自 mock：

| 缺失 API | 桩 |
|---|---|
| `ResizeObserver` | 空实现的 `observe/unobserve/disconnect`（`useElementSize` 依赖） |
| `window.matchMedia` | 恒 `matches: false` 的 `MediaQueryList`（减少动效/明暗判定依赖） |
| `URL.createObjectURL` / `revokeObjectURL` | `vi.fn()` 返回 `'blob:mock'`（图片与下载依赖） |

交付前自查（同一天的记录，方便回滚定位）：

- 改了 `src/render/**` 或 `src/player/**` → 必须重跑 `scripts/build-player.mjs`，否则导出的 HTML 还是旧渲染器。
- 加了 i18n 键 → zh/en 两份同时加，`i18n.test.ts` 会做结构比对。
- 改了 `schema/deck.ts` → 同时看 `factory.ts` 的默认值、`migrate.ts` 的升级分支、`sample-deck.ts` 能否通过校验。
- 改了画布几何 → `stage-geometry.test.ts` 会先红；不要改测试里的期望值，先确认规则本身是否要变。

## 6. 常见问题

| 症状 | 原因 | 处理 |
|---|---|---|
| dev server 崩掉，日志有 `EBUSY` | 编辑器/工具的原子写产生 `*.tmpdir`，chokidar 监听触发文件锁 | 已在 `vite.config.ts` 的 `watch.ignored` 忽略；仍崩就**直接重启** dev server，不要改配置 |
| 端口占用 / `strictPort` 失败 | 已有一个 dev server 在跑 | 复用 `http://127.0.0.1:5273`，不要起第二个 |
| 导出 HTML 打开是空白 / 播放器报错 | `public/player/lumen-player.js` 不存在或过期 | 先 `& $node scripts/build-player.mjs`（`predev`/`prebuild` 会自动跑） |
| `git status` 里看不到 `public/player/` | 它是**构建产物**，`.gitignore` 明确排除 | 不要提交；换机器先构建 |
| 单测里 canvas/ResizeObserver 报错 | jsdom 缺浏览器 API | `tests/setup.ts` 已补桩；新增 API 缺口请补在 setup，而不是在测试里 mock 三次 |
| 导出体积突然超过 12MB | 素材内联（图片 dataURL） | 超过 12MB 只警告并产出，超过 24MB 直接拒绝（`STANDALONE_ABORT_BYTES`）；先压缩/裁剪素材 |
| 3D 幕在缩略图里是渐变占位 | `mode='thumb'` 绝不创建 WebGL | 正常行为；在舞台渲染过一次后才有真实海报 |
| 打印对话框没弹出来 | 浏览器拦截弹窗（`preferWindow` 路径） | 用应用内就地打印（`PrintHost` 已挂载时默认走这条） |
| 中文界面里出现英文键名 | i18n 缺键（dev 会 `console.warn`） | 补 `editor.{zh,en}.ts` 同键；`en` 必须与 `zh` 同结构 |
| 刷新后数据回到示例（数据"失忆"） | IndexedDB 打不开或 store 缺失 → `kv.ts` 静默降级内存模式 | 已是自建单库 `lumen-deck` **v3**、一次 `upgrade` 建齐五个 store（`decks/assets/settings/forge/aiCache`）；排查时看 `storageModeNotice()` 与 `[storage] indexedDB 不可用` 的 warn |
| e2e 卡在 webServer 启动 | 5274 端口被上一次跑残留的进程占着 | `reuseExistingServer: true` 会复用；真起不来就手动关掉占用 5274 的进程 |

### 6.1 调试入口

代码里已有的开关与诊断入口（`data-*` 属性与产物文件可直接查看；模块导出需在代码或调试脚本里取用）：

| 入口 | 作用 |
|---|---|
| `<html data-ui-theme>` | `dark` / `light`，由设置同步（`settingsSync.ts`）写入 |
| `<html data-reduced-motion>` | `'true'` / `'false'`，用户设置；与系统 `prefers-reduced-motion` 取或 |
| `<html data-lumen-forge>` | `'1'` 表示造幕台正在挂载（`ForgeApp.tsx`），关闭即移除 |
| `<html data-lumen-studio>` | `'1'` 表示工作室宿主已注册事件监听（`StudioHost.tsx`） |
| `getLiveThreeRuntimeCount()` | 当前存活的 WebGL runtime 数量（预算上限 4） |
| `dictionaryOf('zh' \| 'en')` | 取扁平词典，查缺键用 |
| `shortcutsInstalled()` | 快捷键表是否已安装（防止重复挂载） |
| `storageModeNotice()` | 是否已降级到内存存储（IndexedDB 不可用时为 true） |
| `harness/out/console-errors.json` | 截图 harness 收集的 console error / pageerror，验收要求为 `[]` |

## 7. 已知限制

- e2e 有 12 个用例：覆盖"主链路不崩"，但没有像素级视觉回归，也没有多浏览器矩阵（只跑 Chrome + SwiftShader）。
- 单测全在 jsdom：没有布局引擎与 WebGL，尺寸/对比度/3D 构图只能断言"结构正确"，真实像素需在浏览器里看。
- 测试与文档里出现的用例数、行数、钩子数量都是采样值，多人并行时会漂移。
- `scripts/probe-*.mjs` 属临时验证脚本，命名与产出不稳定，不进 DoD；把它们当调试工具而不是回归资产。
- 构建链路有顺序依赖（播放器内核先于主构建），CI 若只跑 `vite build` 会拿到旧的 `public/player/`。
- `file://` 下的可播性只能靠 e2e 的 `export.spec.ts` 兜住一条链路（首屏 + 右侧翻 8 次 + 零外部请求），`?print=1` 的 file:// 分支靠人工双击验证。
- `harness/out/export/` 里的历史产物不代表当前构建，比较体积前先重新导出。
