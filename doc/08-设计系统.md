# 08 设计系统 —— 两套令牌、6 套主题与组件基元

> 本文是"视觉决定的唯一出处"：UI 铬色（editor chrome）与演示主题（deck theme）是两套互不干扰的令牌；六套主题是 TS 数据，运行时注入 `--d-*` 变量，导出时序列化同一份。
> 主题的数据契约见 `doc/03-数据模型与DSL.md` §5；渲染细节见 `doc/05-SVG与3D渲染.md`。

## 1. 两套令牌体系

| | UI 铬色 | 演示主题 |
|---|---|---|
| 前缀 | `--ui-*` | `--d-*` |
| 定义处 | `src/styles/tokens.css`（静态 CSS） | `src/themes/index.ts`（TS 数据）+ `themeCssVars()` |
| 作用域 | `:root`（跟随 `<html data-ui-theme>` 切明/暗） | 注入到 `.stage-frame` / `.lumen-slide` / `.panel` / 播放舞台根节点 |
| 变量数量 | `:root` 声明 31 个，其中 24 个是颜色/画布类 | 每次注入 50 个（7 色 + 2 派生色 + 3 字体 + 圆角 + 2 动效 + 5 纹理/光晕/层次 + 1 纹理瓦片 + 7 变体 × 4） |
| 明暗 | `[data-ui-theme='light']` 覆盖 26 个（24 色 + 2 阴影） | 主题本身就是明/暗的完整方案，没有模式切换 |

### 1.1 `--ui-*` 分组

| 组 | 令牌 |
|---|---|
| 底色 | `--ui-bg` `--ui-bg-2` `--ui-panel` `--ui-panel-2` `--ui-elev` `--ui-hover` `--ui-active` `--ui-canvas` |
| 分隔 | `--ui-line` `--ui-line-strong` |
| 文本 | `--ui-fg` `--ui-fg-dim` `--ui-fg-mute` `--ui-fg-invert` |
| 强调/语义 | `--ui-accent` `--ui-accent-2` `--ui-accent-soft` `--ui-accent-line` `--ui-danger` `--ui-danger-soft` `--ui-ok` `--ui-warn` `--ui-info` |
| 阴影 | `--ui-stage-shadow` `--ui-shadow` `--ui-shadow-sm` |
| 形状 | `--ui-radius` `--ui-radius-sm` `--ui-radius-xs` |
| 字体 | `--ui-font` `--ui-font-mono` |
| 尺寸 | `--rail-w` `--panel-w` `--topbar-h` `--sheet-w`（不带 `ui` 前缀） |
| 层级 | `--z-stage` `--z-guides` `--z-overlay` `--z-popover` `--z-modal` `--z-toast` |

明暗切换只换颜色：`--ui-radius*` 与 `--ui-font*` 在浅色块里不重声明。半透明一律用 `color-mix(in srgb, <token> N%, transparent)`，不引入第三套色板。

### 1.2 `--d-*` 的生成

`themeCssVars(theme, overrides)` 的输出（按顺序）：

```ts
'--d-bg' '--d-fg' '--d-muted' '--d-surface' '--d-line' '--d-accent' '--d-accent2'   // 7 色，overrides 合并后
'--d-surface-2' '--d-accent-soft'                                                   // 2 个派生色（v0.2.5）
'--d-font-body' '--d-font-display' '--d-font-mono'                                  // 3 套字体栈
'--d-radius' '--d-ease' '--d-motion-ms'                                             // 圆角与动效
'--d-texture' '--d-texture-op' '--d-glow' '--d-elevation'                           // 纹理 / 光晕 / 层次（v0.2.5）
'--d-shadow-1' '--d-shadow-2' '--d-texture-image'                                   // 档位阴影 + 纹理瓦片（v0.2.5）
'--d-fs-<variant>' '--d-lh-<variant>' '--d-fw-<variant>' '--d-tk-<variant>'          // 7 变体 × 4 = 28
```

- 字号已乘 `typeScale` 并四舍五入到 0.1px；`--d-tk-*` 单位是 `em`。
- 三个一次性入口：`themeCssVars()`（React 内联样式）、`themeVarsCss(vars, selector)`（拼一段 CSS）、`themeInlineStyle()`（导出用的纯声明串）。
- 派生色不落库：`--d-surface-2` / `--d-accent-soft` 由 7 色现算（`surface2Of` / `accentSoftOf`），改强调色时二级表面与软底自动跟随。
- three 取色不读 CSS 变量，而是拿同一份合并色 `{...theme.colors, ...deck.themeOverrides}` 传给 `ThreeView`，保证 CSS 与 WebGL 同源。

## 4. 排版规则

| 规则 | 实现（`render/slide.css`） |
|---|---|
| `display` / `h1` / `h2` 用 display 字体 | 三者的 `font-family` 都指向 `--d-font-display`；只有 display 与 h1 加 `text-wrap: balance` |
| `lead` / `body` / `caption` 用 body 字体 | 继承 `.lumen-text` 的 `--d-font-body`；`caption` 不转大写（`text-transform: none`） |
| `mono` 用等宽栈 | `--d-font-mono`，常用于代码块与标签 |
| 段间距 | `.lumen-para + .lumen-para { margin-top: 0.55em }`，与 lint 的换行估算同一口径 |
| 强调 | `strong` 固定 700 且强制 `--d-fg`（不回落到 muted）；`em` 只做斜体 |
| 行内代码 | `.lumen-code`：`0.86em`、`padding 0.1em/0.34em`、圆角 4px、底色 `--d-accent-soft`（accent 12%，v0.2.5 起）、文字 `--d-accent` |
| 换行 | `.lumen-text` 是 `pre-wrap` + `overflow-wrap: anywhere` + `text-wrap: pretty`，显式 `\n` 生效 |
| 溢出 | 文本块 `overflow: hidden`，溢出由 lint 的 `textOverflow` 报，不靠滚动条 |

## 5. 间距、栅格与外壳尺寸

- 舞台：1600×900，安全边距 x 120 / y 96；12 列栅格 gap 24，列宽 ≈91.33（细节见 `doc/03-数据模型与DSL.md` §9）。
- 外壳：`--topbar-h 52px`、`--rail-w 216px`、`--panel-w 340px`、`--sheet-w 60px`；舞台视口 `padding: 28px`，舞台投影 `--ui-stage-shadow`。
- 圆角：`--ui-radius 10 / --ui-radius-sm 7 / --ui-radius-xs 5`；演示侧用 `--d-radius`（主题 0–14），SVG/HTML/3D 容器都吃这个值。
- 阴影：`--ui-shadow`（弹窗）、`--ui-shadow-sm`（浮条/HUD）、`--ui-stage-shadow`（舞台），都用低透明度黑 + 1px 高光。
- 层级：令牌 `--z-stage 1 / guides 20 / overlay 40 / popover 60 / modal 80 / toast 92`；但 `stage.css` 里选择框/覆盖层/拖放提示直接写了 `z-index: 5/10/30/60`，两套并存（见 §9）。

## 7. 组件基元

`src/ui/primitives/index.ts` 是唯一出口（20 个具名导出）：

| 类别 | 组件 |
|---|---|
| 按钮 | `Button`（`primary/outline/ghost/subtle/danger` × `sm/md`，可选 `icon` `block` `active`）、`IconButton`（`label` → `title` + `aria-label`，`active` → `aria-pressed`，`tone: 'danger'`） |
| 布局 | `Section` `Row` `Field` `PanelHeader` |
| 输入 | `TextInput` `TextArea` `NumberInput` `Select` `Segmented` `Switch` `Slider` `ColorSwatches` |
| 浮层 | `Modal` `Popover` `PopoverLabel` `PopoverRow` `PopoverSeparator` `Toasts` |

使用边界：

- UI 一律用基元 + `--ui-*`，**不要**在面板里手写按钮/输入框样式；`primitives.css` 已覆盖 hover/focus/disabled。
- 演示内容一律用 `--d-*`；面板若要预览主题色（色板、主题页签），在面板根节点注入 `themeCssVars()`（`Inspector` 就是这么做的）。
- 图标统一 `lucide-react`；图标按钮必须有 `label`（无可见文案时的可访问名）。
- 输入框焦点态是 `border-color: --ui-accent-line` + `box-shadow: 0 0 0 3px --ui-accent-soft`，并显式 `outline: none`——键盘焦点可见性由全局 `:focus-visible` 兜底。

## 8. 可访问性

| 项 | 实现 |
|---|---|
| 对比度 | `lint/color.ts` 解析 `#hex/rgb()/hsl()` 并算 WCAG 比值；`deckLint` 的 `contrast` 规则：正文 < 4.5、大字 < 3（大字 = ≥24px，或 ≥18.66px 且 weight ≥700） |
| 对比度兜底 | AI 配方写色前先算比值，不达标自动退回 `fg`（`recipes.ts` 的 `aaThreshold/contrastRatio`） |
| 焦点环 | 全局 `:focus-visible { outline: 2px solid var(--ui-accent); outline-offset: 1px }`；`::selection` 用 `--ui-accent-soft` |
| 减少动效 | 系统 `prefers-reduced-motion` → `base.css` 把 `--dur-*` 归零且动效时长 0.001ms；`slide.css` 关掉 SVG/入场动效与 accent 光晕呼吸（**纹理是静态图层，照旧保留**）；`useReducedMotion()` 还叠加用户的 `reducedMotion` 设置；`<html data-reduced-motion>` 供 CSS 选择 |
| 语义 | 面板 `role="tablist"/"tab"` + `aria-selected`、手柄 `role="button"` + `aria-label`、`aria-pressed` 用于开关按钮 |
| 屏幕阅读器 | `.lumen-sr`（视觉隐藏但可读）；装饰节点带 `aria-hidden` |
| 纯装饰不抢事件 | `.stage-overlay` 除手柄外 `pointer-events: none`，`aria-hidden` 只用于纯装饰层 |

## 9. 已知限制

- 层级有两套来源（`--z-*` 令牌与 `stage.css` 里的裸数字），改层级要先搜 `z-index`，不能只改令牌。
- `--ui-*` 的浅色覆盖只做了 26 个变量；新增颜色令牌若忘记补浅色值，会在明色主题下沿用暗色值。
- 主题覆盖 7 个颜色 + 派生表面/软底 + 字体/比例/圆角/动效 + 纹理/光晕/层次（v0.2.5），**仍然没有**间距、栅格与密度维度，"换主题"不会改变版式节奏；`--d-texture` / `--d-elevation` 只是档位名，视觉由 `--d-texture-image` 与 `--d-shadow-1/2` 承载（CSS 无法按变量值分支）。
- `--ui-font*` 与 `--d-font-*` 是两份独立字体栈：UI 永远无衬线，只有演示里的 display 字体可能是衬线，两者不联动。
- 演示字号是"主题 × 变体"的二维表，块级 `weight/lineHeight/tracking` 覆盖会直接写进 deck，换主题后这些硬编码值不会跟着变（lint 的字号下限仍会检查）。
- 对比度 lint 只比较"文本色令牌 vs 幕背景色"，不感知文本下方的形状/图片，因此是提示而非断言。
- 终端主题用 `steps(6, end)` 做动效曲线，在某些属性（如 opacity 之外的渐变）上观感不一致，属于该主题的刻意风格。

## 11. v0.2.5 设计预设打磨（纹理 / 光晕 / 层次）

「优化现有 design 预设」是 v0.2.5 的两条主线之一：**不新增主题**，只把六套已有的预设打磨到可量化验收（对比度）、并补上"表面质地"这个一直缺的维度。前置决策与逐套前后对照见 `plan/v0.2.5/04-设计预设.md`。

### 11.1 三个新字段（全部可选）

```ts
texture: z.object({ kind: z.enum(['none','grain','grid','scan','dots']), opacity: z.number().min(0).max(1) }).optional(),
glow: z.number().min(0).max(1).optional(),        // accent 光晕强度
elevation: z.enum(['flat','raised','layered']).optional(),
```

- 旧 Deck 反序列化不受影响：工程文件只存 `themeId` + `themeOverrides`，从不存主题对象；解析函数也把它们当可选字段。
- 旧主题对象（缺这三个字段）走默认值 `none / 0 / flat`，渲染结果与 v0.2.0 逐像素一致（`tests/unit/themes-v025.test.ts` 有断言）。
- `kind: 'none'` 时 `--d-texture-op` 被归一成 `0`，避免"没有图案却铺了一层墨"。

### 11.2 新增变量与派生色纯函数

| 变量 | 含义 | 生成方式 |
|---|---|---|
| `--d-texture` | 纹理档位名 | `theme.texture?.kind ?? 'none'` |
| `--d-texture-op` | 纹理强度 | `textureOpacityOf()`，`none` → `0`，越界夹到 0..1 |
| `--d-glow` | accent 光晕强度 | `theme.glow ?? 0`，夹到 0..1 |
| `--d-elevation` | 层次档位名 | `theme.elevation ?? 'flat'` |
| `--d-surface-2` | 二级表面 | `surface2Of(bg, surface)`：深色提亮 7%、浅色压暗 5% |
| `--d-shadow-1` / `--d-shadow-2` | 一档/二档阴影 | `shadowsOf(elevation, bg)`：flat `none`、raised/ layered 两档叠加 |
| `--d-accent-soft` | accent 12% 软底 | `accentSoftOf(accent)` → `rgba(r, g, b, 0.12)` |
| `--d-texture-image` | 纹理瓦片（内部派生） | `textureTileOf(kind)`：alpha 遮罩用的 data URI 瓦片 |

派生色全部是**纯函数**（`parseThemeColor` / `toHexColor` / `mixColor` / `darkenColor` / `lightenColor` / `withAlpha`），解析不了的颜色退回 CSS `color-mix()`，导出样式永远合法。契约列了 8 个变量，实际输出 9 个：`--d-texture-image` 是内部派生——CSS 没法用关键字选图案，而本轮写作用域不含渲染器，把"kind → 瓦片"放在 `themeCssVars` 里是最小改动且导出同源的做法。

**accent / accent2 用法**（v0.2.5 明确）：`accent` 是唯一主强调（短横线、焦点、数据高亮、最后一个柱），每幕最多 2 次；`accent2` 只做次强调与反衬（图表第二序列、装饰圆点、双色渐变），不与 accent 同权重并列、不用于正文。需要"面"用 `--d-surface-2`，需要"软底"用 `--d-accent-soft`。小字要上 accent 时由 `recipes.ts` 的 `ink()` 按 `aaThreshold` 自动退回 `fg`（`signal` 的电红 4.13 就靠这条守可读性）。

**圆角与动效曲线**：六套逐套复核后**保持原值**（`radius 0–14`、`motion 300–560ms`）。它们正是各主题的性格来源，改动的收益远小于全局视觉 diff；逐套理由见 `plan/v0.2.5/04-设计预设.md` §5.2。

### 11.3 `slide.css` 的消费点

| 层 | 选择器 | 用法 |
|---|---|---|
| 纹理 | `.lumen-slide::before` | `mask-image: var(--d-texture-image)` 平铺整幕，墨色 `fg 55%`，`opacity: var(--d-texture-op)`；`z-index: -1` 压在内容块之下 |
| 光晕 | `.lumen-slide::after` | 两个径向渐变（`--d-accent-soft` + accent2 10%），`opacity: var(--d-glow)`；只有 `[data-mode='play']` 才有 `lumen-glow-breathe` |
| 层次 | `.lumen-image` / `.lumen-three` / `.lumen-html` / `.lumen-placeholder` / `.lumen-code` | 媒体框吃 `--d-shadow-1`、3D 焦点媒体吃 `--d-shadow-2`，flat 主题两者都是 `none` |
| 二级表面 | 图像骨架、3D 降级底、SVG 徽标、占位框 | `color-mix(..., var(--d-surface-2) N%, transparent)` |

静止态（`[data-mode='stage'|'thumb'|'print'|'export']`、`[data-forge-still='1']`、`[data-still='1']`、`[data-reduced-motion='true']`、`prefers-reduced-motion`、打印层）只关光晕动画，**纹理照旧**——纹理不是动效。

### 11.4 对比度验收（脚本实测，`tests/unit/themes-v025.test.ts` 同口径）

正文 `fg/bg ≥ 7:1`、辅助文本 `muted/bg ≥ 4.5:1`、强调色 `accent/bg ≥ 3:1`（`accent2` 同口径），并把同组阈值搬到二级表面上（`muted/surface-2 ≥ 4.5`、`accent/surface-2 ≥ 3`），因为卡片里真的会落字。

| 主题 | fg/bg | muted/bg | accent/bg | accent2/bg | muted/surface-2 | accent/surface-2 |
|---|---|---|---|---|---|---|
| `noir` | 17.16 | 6.58 | 8.09 | 7.79 | 5.01 | 6.16 |
| `paper` | 15.84 | 6.06 | 5.37 | 5.51 | 4.92 | 4.36 |
| `aurora` | 16.94 | 7.44 | 12.33 | 7.67 | 5.42 | 8.97 |
| `signal` | 17.97 | 6.16 | 4.13 | 6.58 | 4.89 | 3.28 |
| `museum` | 12.90 | 6.07 | 5.05 | 4.62 | 4.87 | 4.05 |
| `terminal` | 17.30 | 6.65 | 11.42 | 11.92 | 5.23 | 8.99 |

v0.2.0 的 `museum` 是唯一不达标的（muted/bg = 4.40），本轮把 `muted` 从 `#6f675c` 压到 `#5a5247`；`noir` / `aurora` / `terminal` 的 muted 提亮是为了让"卡片里的 muted"也过 4.5。

### 11.5 导出一致性

编辑器与导出走同一条链，没有第二份样式：

1. `themeCssVars(theme, overrides)` → React 内联（`SlideRenderer`、`Inspector`、`Stage`、`PrintPages`）；
2. `themeVarsCss(...)` → `:root{...}` 内联进独立 HTML 的 `<style id="lumen-theme">`；
3. 纹理/光晕/阴影的**规则**在 `src/render/slide.css`，播放器内核构建时被打进 `public/player/lumen-player.css`，导出把它整份内联。

因此判定方法不需要像素比对：`tests/unit/themes-v025.test.ts` 断言「变量表 → 内联串 → 独立 HTML 里同一批 `--d-*` 都在」，并另有一条"构建产物与源码同源"的断言（`public/player/lumen-player.css` 里必须有 `--d-texture-image` 与 `lumen-glow-breathe`）。打印走 `PRINT_CSS` 的 `print-color-adjust: exact`，纹理与阴影不会被浏览器省掉。

另做过一次真文件闭环：点「导出 → 生成文件」把下载到的 HTML 用 `file://` 重开，读 computed style——`terminal` 的 `--d-texture: scan` / `0.06`、`--d-glow: 0.55`、`::before` 的 mask data URI、播放中的 `lumen-glow-breathe 7.2s` 全部到位；`paper` 的 `--d-shadow-2` 在导出文件里 `.lumen-three` 的 `box-shadow` 上逐字相同。**编辑器所见 = 导出所得**，不是靠肉眼。

### 11.6 仍未做

- 纹理与层次**不进** recipe 版式：卡片阴影没落在 `shape` 块上（`ShapeView` 没暴露 `fill`，本轮写作用域不含渲染器），卡片靠 `surface-2` + `line` 分层。
- `--d-texture` / `--d-elevation` 是档位名，CSS 不按变量值分支（真要分支得上 `@container style()`，浏览器支持面还不够）。
- 3D 舞台取色仍只读 7 色，不读 `surface-2` / `glow`；`ThreeView` 的 grain 与主题纹理是两套。
