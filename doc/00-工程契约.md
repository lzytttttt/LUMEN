# LUMEN 工程契约（多人并行开发的唯一共同约定）

> 本文件是给「同一个仓库里的多个实现者」看的。改代码前先读 §2 所有权 与 §5 验证。
> 产品主张与设计原则见 `doc/01-产品概述.md`（Wave 3 补齐）；本文件只谈工程事实。

## 1. 技术事实（不要改）

- 技术栈：React 19 + Vite 7 + TypeScript 5.9（strict）+ zod 3 + zustand 5 + immer 11 + three r186 + DOMPurify 3 + CodeMirror 6。
- 路径别名 `@/` → `src/`。**不要新增运行时依赖**；缺能力先问 Lead。
- 舞台坐标系固定 **1600 × 900**，安全边距 120/96。所有块几何都是设计像素；缩放只在外层 `transform: scale()` 做一次。
- 主题是 TS 数据（`src/themes/index.ts`）→ 运行时 CSS 变量 `--d-*`；导出时同一份数据序列化，保证编辑器与导出物一致。
- 只在系统字体栈内排版（`--d-font-body/display/mono`），不加载外链字体。
- `src/schema/deck.ts` 是数据契约（zod）。**不要改字段名/结构**；确实需要新字段先找 Lead。
- 状态：`src/state/deckStore.ts`（immer 补丁历史）+ `src/state/ops.ts`（唯一写入口）。
  **组件绝不直接改 deck 对象**，一律 `deckOps/slideOps/blockOps/historyOps`。
- i18n：`t('ns.key', vars)` / `useT()`；zh 为类型源，**en 必须同键**（`tests/unit/i18n.test.ts` 会红）。
- UI 文案不许硬编码中文；deck 内容（示例、AI 生成物）除外。

## 3. 渲染契约

```tsx
<SlideRenderer deck={deck} slide={slide} mode="stage|play|thumb|print|export"
               active? editingBlockId? theme? />
```
- 固定 1600×900；调用方负责缩放（`transform: scale()` + `transform-origin: top left`）。
- `mode='stage'`：块内容 `pointer-events: none`，命中测试由 `Stage` 用几何计算；只有 `editingBlockId` 对应的块可交互。
- `mode='thumb'`：不初始化 WebGL、不跑动效、不加载远端资源。
- `mode='play'`：允许 three 动画、入场动效、HTML 沙箱交互。
- 所有块必须定义在 1600×900 内（允许少量出血），溢出写入 lint。

## 5. 本地命令（必须用仓库内的 node）

```powershell
$node="C:\Users\Administrator\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe"
& $node node_modules/typescript/bin/tsc --noEmit          # 类型
& $node node_modules/vitest/vitest.mjs run               # 单测
& $node node_modules/vite/bin/vite.js build              # 生产构建
& $node scripts/dev-server.mjs 5273                      # 开发服（已有一个在跑就先复用 http://127.0.0.1:5273）
& $node scripts/snapshot.mjs http://127.0.0.1:5273       # 截图到 harness/out/
```

- 开发服已在后台跑时直接访问 `http://127.0.0.1:5273`；**不要**再起第二个（`strictPort` 会失败）。
- 若开发服被文件锁崩掉（EBUSY），直接重启它，不要改配置。
- 原子写会短时间产生 `*.tmpdir`，已在 vite 配置里忽略；不要手工清理 `src` 下的临时目录。

## 6. 交付与回报格式

每个任务完成时，用 `send_message` 回报给 lead：

```
FILES: 新增/修改的文件（按目录）
VERIFIED: 跑了哪些命令、结果（tsc/vitest/build/截图）
API_NEEDED: 需要 Lead 补的 store action / primitive / i18n 键（若有）
RISKS: 已知风险与未完成项
```

验收底线：`tsc --noEmit` 0 error、单测全绿、`vite build` 通过、无 console error。
不要提交 git，不要动 `package.json`。
