# 06 AI 编排 —— 通道、提示词、修复环与 12 个配方

> 本文写 `src/ai/**` 的实现事实：通道抽象与错误码、5 套 system prompt 的契约、JSON 修复环、12 个版式配方（含字阶自适应）、确定性语料/素材，以及三条管线（大纲、逐幕、微调）与溯源。
> 产出的数据结构见 `doc/03-数据模型与DSL.md`；AI 产物要过的尺子见 `doc/05-SVG与3D渲染.md` §5。

## 1. 模块分层

| 文件 | 职责 |
|---|---|
| `index.ts` | 唯一对外出口（compose / refine / intent / recipes / provider / validate / corpus / art / generate / provenance） |
| `provider.ts` | `AiProvider` 抽象、Mock 与 OpenAI 兼容实现、`AiError` 与路由 |
| `prompts.ts` | 5 套 system prompt + 请求构造函数（`[TASK:x]` 标记） |
| `validate.ts` | `extractJson` → zod 校验 → 一次修复回喂 |
| `recipes.ts` | 12 个版式配方（AI 的"品味"在这里，不在模型里） |
| `corpus.ts` / `art.ts` | 离线确定性语料与素材（4 意图 × 2 语言 / 5 风格 SVG / 3D 描述符） |
| `compose.ts` | 一句话 → 大纲 → 逐幕成稿（含单幕 lint 与降级） |
| `refine.ts` | 自然语言微调（规则优先，LLM 只做增强）+ patch plan |
| `intent.ts` | `lumen:intent` 事件路由 → 具体编辑动作 |
| `generate.ts` | 单点生成 SVG / 3D（失败回退本地素材） |
| `provenance.ts` | `provenance` + `aiSnapshot` 打戳 |
| `ui/**` | `ComposerPanel`、`OutlineEditor`、`GenerationProgress`、`RefineBox` |

依赖方向严格单向：`ai/**` 可以读 `schema`、`themes`、`lint`、`state.ops`，但**渲染层完全不认识 AI**。

## 2. 通道抽象

```ts
interface AiProvider {
  id: 'mock' | 'openai'
  label: string
  complete(req: { system: string; user: string; json?: boolean; temperature?: number; signal?: AbortSignal }): Promise<{ text: string; usage?: { prompt: number; completion: number } }>
}
```

只有一个能力：`system + user → text`。提示词、校验、重试都在调用方，换通道不改管线。

### 2.1 Mock 通道（默认）

- `MOCK_LATENCY_MS = 110`（`import.meta.env.MODE === 'test'` 时为 0），让进度条与"取消"有意义。
- 从 system 首行的 `[TASK:outline|slide|svg|three|refine]` 读任务标记，从 user 里抠第一个 JSON 对象当输入。
- 产出仍是 JSON 文本：`mockOutline` / `mockSlideContent` / `mockSvgArt` / `mockThreeScene`，**同一 prompt 永远同一结果**（`seedFrom` + mulberry32）。
- `usage` 用 `ceil(len/4)` 估算，只为 UI 有个数。

### 2.2 OpenAI 兼容通道

- 端点归一：`baseURL` 去尾斜杠，若不是以 `/chat/completions` 结尾就补上。
- 请求体：`{ model, messages: [system, user], temperature, stream: false }`；`jsonMode` 打开且调用方要 JSON 时加 `response_format: { type: 'json_object' }`。
- **jsonMode 降级**：`400/404/422` 且响应体里出现 `json` → 去掉 `response_format` 重试一次（兼容不支持该参数的端点）。
- 超时 `Math.max(1000, timeoutMs || 90_000)`；外部 `signal` 与内部超时共用一个 `AbortController`。
- 内容解析兼容 `content: string` 与 `content: [{text}]` 数组两种形态；空内容直接判 `badJson`。
- 鉴权头只在 `apiKey` 非空时加 `authorization: Bearer …`（本地 Ollama 不需要）。

### 2.3 错误模型

| code | 触发 | 用户可见文案来源 |
|---|---|---|
| `notConfigured` | `baseURL` / `model` 为空 | `ai.error.notConfigured` |
| `auth` | HTTP 401 / 403 | `ai.error.*` + detail 片段（≤180 字符） |
| `timeout` | 超过 `timeoutMs`，或用户取消（`detail === 'aborted'` 且 `aborted = true`） | `ai.error.aborted` |
| `badJson` | 响应不是 JSON、`choices[0]` 为空、修复环用尽 | `ai.error.badJson` |
| `network` | fetch 抛错、其它非 2xx | 原始 message |

`isAborted(err)` 把 `AiError.aborted`、`timeout + 'aborted'` 与 `DOMException: AbortError` 统一成"用户取消"——**取消不弹错误 toast**。

## 3. 五套 system prompt

每条 prompt 都做三件事：声明输出契约（JSON 摘要）、声明禁止项、声明语言跟随输入。首行 `[TASK:x]` 只给 Mock 分派，真模型会忽略。

| 常量 | 标记 | 输入 | 输出契约 |
|---|---|---|---|
| `OUTLINE_SYSTEM` | `[TASK:outline]` | `outlineRequest()` 打包 prompt/lang/audience/length/slideCount/durationMin/开关 | `{ title, subtitle?, lang, slides[] }`，每幕 `recipe + headline + lead? + points[] + visual + notes?` |
| `SLIDE_SYSTEM` | `[TASK:slide]` | 大纲标题、幕序/总数、该幕种子 | `{ headline, lead?, points[], notes? }` |
| `SVG_SYSTEM` | `[TASK:svg]` | prompt + style + viewBox 820×560 | `{ svg, viewBox, caption }` |
| `THREE_SYSTEM` | `[TASK:three]` | prompt | `{ descriptor }`（受限枚举 + 预算说明） |
| `REFINE_SYSTEM` | `[TASK:refine]` | 指令 + 语言 + 当前 recipe/headline/lead/points | `{ headline, lead?, points[] }` |

`COMMON_RULES`（五套共用）的硬性禁止：

1. 只输出 JSON，不写 CSS/JS/HTML 片段与解释文字；
2. 不使用外链（图片/字体/脚本/CDN）；
3. 不输出 `<script>`、事件属性、`foreignObject`、`<style>`；
4. 颜色只能引用主题令牌 `bg/fg/muted/surface/line/accent/accent2`；
5. 不编造统计口径（示例数据必须标"示意"）。

`OUTLINE_SYSTEM` 另带 `RECIPE_GUIDE`：逐个说明 12 个配方的适用场景与"要点分隔符"（`data` 用「标签=数值」，`timeline` 用「时间｜标题｜说明」，`process` 用「步骤｜时长｜说明」，`compare` 用「组名｜一句话」），并要求 cover 必须第一幕、closing 必须最后一幕、不连续三幕用同一配方。

`outlineRequest()` 把 `length` 折算成建议幕数：`short 6 / normal 9 / deep 12`，并与 `durationMin` 一起下发（LLM 可据此增减，最终由 `normalizeOutline` 收敛到 3–20 幕）。

## 4. 校验与修复环

```ts
parseWithRepair(schema, text, { repair, signal, maxRepair = 1 }) → T   // 失败抛 AiError('badJson')
```

1. `extractJson()`：先剥 ```json 围栏，再从第一个 `{` 起做**字符串感知的括号配平**（跳过 `"` 内的 `{`/`}` 与转义），括号不平衡时退化为"到最后一个 `}`"。
2. `JSON.parse` → `schema.safeParse`；成功即返回。
3. 失败把 `zodIssues()`（最多 8 条 `path: message`）交给 `repair(issues)`：只有 **OpenAI 通道**才提供修复回调，用 `repairPrompt(user, issues)` 追加"上一次输出没通过校验…请只输出修正后的 JSON"，再请求一次。
4. 仍失败 → `AiError('badJson', 前 4 条 issue)`。Mock 通道不重试（它本来就确定）。

修复环是"一次"，不是循环：`maxRepair = 1`（可传更大值，但管线里没人传）。

## 5. 12 个版式配方

配方的输入只有槽位（`headline / lead / points / visual / caption / notes / index / total`），**AI 不产出任何几何**。

| id | 典型用途（来自 `RECIPE_GUIDE`） | 版式要点（已核对） |
|---|---|---|
| `cover` | 封面，必须第一幕 | kicker（caption/accent）+ 标题（`COVER_LADDER`）+ 96px 短线 + lead，整组在 y 200–700 里垂直居中（`centerGroup`），页脚 caption；有视觉时右栏 620×660（three 580×680） |
| `statement` | 一句大字 + 一行注解的转折页 | 居中标题（`STATEMENT_LADDER`）+ 80px 短线 + muted 的 lead |
| `split` | 左文右图 / 两列要点 | 有 visual 时右栏 740×660（three 为 760×680），要点最多 3 条并动态分配高度；无 visual 时两列各 640 |
| `grid3` / `grid4` | 3 / 4 个并列要点 | 等宽卡片：`cardW = (1360 − 24 × (n−1)) / n`，卡片高 300，标题走 `header()` |
| `timeline` | 2–5 个节点的时间线 | 中轴线 `y = 462` + 18px 圆点；`时间｜标题｜说明` 拆三段；逐点 `enter: 'rise'` 错峰 70ms |
| `compare` | 左右对比 | 左右各最多 3 条，标题 muted/accent 分色，中间一条 **1px 竖分隔**（回归测试靠这条断言） |
| `quote` | 一句可被复述的话 + 出处 | `QUOTE_LADDER`（>20 em 降一档）+ 80px 短线 + caption 出处 |
| `data` | 标签=数值的数据页 | 左侧柱状条（shape 块）+ 环形图（纯 SVG `donutSource()`，420×420，令牌色）；右侧「结论」h2 + lead + 1px 线 + "示意数据" caption |
| `process` | 3–5 步流程 | 等宽面板 `panelW = (1360 − 24×(n−1))/n`、高 220：编号（caption/accent）+ h2 标签 + 说明，面板之间用三角箭头 |
| `gallery` | 3 条图注的图集 | 三栏等高面板（高 420），每栏一张 SVG（精选库轮取，缺则 `mockSvgArt`）+ 底部图注 |
| `closing` | 收尾，必须最后一幕 | `COVER_LADDER` 标题 + lead 整组居中（240–720）+ 页脚 + 可选视觉（560×580/600） |

### 5.1 字阶自适应（`emWidth`）

```ts
// CJK 记 1 em、空白 0.3、拉丁 0.55 —— 中英混排统一估算
emWidth('演示，该换一种载体了')   // 10.0（10 个全角字符）
emWidth('演示 AI')                // 3.4（2 + 0.3 + 0.55×2）
headlineVariant(text, COVER_LADDER)  // 10 em ≤ 10 → 'display'；11–18 → 'h1'；>18 → 'h2'
```

四张阶梯：`COVER_LADDER`（10/18/∞ → display/h1/h2）、`STATEMENT_LADDER`（20/∞ → h1/h2）、`QUOTE_LADDER`（20/∞ → display/h1）、`TITLE_LADDER`（16/∞ → h2/lead，内容页标题超长时降到 lead 并加 600 字重）。**"自觉"交给版式，不交给模型**。

### 5.2 兜底与"不得静默退回 statement"

- `fillContent(id, content)` 按配方取自己的兜底文案（`FALLBACK[recipeId][lang]`），缺项补文案而不是换版式。
- `ink()` 在写色前算 WCAG 对比度，不达标自动退回 `fg`——6 套主题都不会出现"看不清的强调色"。
- `buildRecipe()` 只在**配方自己抛错**时 `catch` 到 `statement`（最后一道保险），正常路径绝不发生。
- 回归测试明确约束：`cover/split/grid3/grid4/timeline/compare/data/process/gallery` 产出的块数必须 > 4，且 `compare` 必须出现 1px 竖分隔与 ≥2 个 h2、`data` 必须有 ≥4 个 rect——即**每个配方都必须真的用上自己的版式**。

## 6. 确定性语料与素材

### 6.1 `corpus.ts`

- 四种意图 `launch / plan / course / retro`（关键词正则，命中不到默认 `plan`），中英各一套语料包。
- `targetCount(length, durationMin)`：`6 / 9 / 12`；`≤5 分钟` 减 2（下限 5），`≥20 分钟` 加 2（上限 14）。
- `selectSeeds()`：保首尾，中间按 `weight`（1 必留 / 2 常规 / 3 深讲）取，保证 SVG/3D 幕在常规篇幅里出现。
- `topicOf()` 去壳（"帮我做一份…""write a deck about…"），CJK 截 22 字、拉丁截 48。
- `mockSlideContent()`：不足 3 条要点时从 `EXPAND_BANK` 补，备注从 `NOTE_BANK` 取（都是"怎么讲"不是"讲什么"）。
- `translateText()` 只是一张词表（各 19 对），够 Mock 演示；真翻译走 LLM。

### 6.2 `art.ts`

- 5 种风格 `orbit / grid / wave / stack / arc`，画布固定 **820×560**；颜色只用 `var(--d-*)`，`defs` 里的渐变 id 带 prompt 种子。
- `pickArtStyle()`：关键词优先（轨道/网格/波/叠/弧），否则用 `seedFrom(prompt)` 选。
- `mockThreeScene()` 只产受限枚举：preset / palette / light / motion 都在 schema 枚举内，`objects` ≤24，`orbitControls: false`，camera 按 preset 给不同 distance。

## 7. 三条管线

### 7.1 大纲（`composeOutline`）

`provider.complete(OUTLINE_SYSTEM)` → `parseWithRepair(outlineSchema)` → **`normalizeOutline()`**：

- 幕数截到 20，空 headline 补"未命名一幕 / Untitled slide"，空要点丢弃、最多 6 条；
- `includeSvg === false` 时把 svg 视觉降为 `none`，`include3d === false` 同理；
- 3D 预算：整篇最多 2 幕（与 lint 的 `threeBudget` 同一条尺子）；
- 不足 3 幕时补幕（cover / closing），最后过一遍 `outlineSchema.parse`。

### 7.2 逐幕成稿（`buildDeckFromOutline`）

```
runPool(slides, limit = 2)
  └─ buildOneSlide(seed, index):
       1. 文案：SLIDE_SYSTEM → parse（失败只记录 warning，用大纲原文兜底）
       2. 视觉：svg/three 走 generate.ts（真端点失败自动回退本地素材）
       3. 排版：buildRecipe(seed.recipe, content, theme) + stampBlocks（provenance/aiSnapshot）
       4. 单幕 lint：error → fallbackRecipeFor(content)（≥3 要点用 grid3，否则 statement）重排一次
warnings 形如 `#3 lint textOverflow → fallback grid3`；进度经 onProgress(done, total)
最后 historyOps.transaction('ai-build-deck') → deckOps.applyOutline(…, { replace: true })
```

- **单幕失败只降级这一幕**，不中断整套；`isAborted` 会立刻向上抛。
- 落库是一步撤销；`meta.origin = 'ai'`、`meta.prompt` 记下原始提示。
- `rebuildOutlineSlide()` + `applySlideRebuild()` 用于"部分失败后单幕重试"（Composer 的 warning 列表里每条 `#n` 都带重试按钮）。

### 7.3 微调（`refineSlide`）

- **规则优先**：10 条正则 → `translate / timeline / process / compare / add3d / addSvg / quieter / shorter / grid / restyle`；命中就不发网络请求（离线可用）。
- 未命中（`unknown`）且端点就绪才走 `buildByModel()`（`REFINE_SYSTEM` + 修复环，`summaryKey = ai.intent.rewrite`）。
- 规则阶段的局部变换：`shorter` 按变体裁字（caption 0.7、display/h1 0.55、其它 0.5）；`restyle` 把 accent 换 accent2；`translate` 走词表；`timeline/process/compare` 用 `｜` 重写要点。
- 产出的是 **`SlidePatchPlan`**（`nextBlocks` + `diff: {removed, added, changed}` + `summaryKey` + `warnings`），调用方预览后再 `applyRefinePlan()`（一个事务：remove → add/replace → 写回 `slide.recipe`）。

### 7.4 意图路由（`intent.ts`）

`window` 事件 `lumen:intent`（detail 可传字符串或 `{ text, scope }`）：

1. 命中主题正则 → `deckOps.setTheme(nextThemeId(...))`（浅色/暗色各有一个候选池）；
2. 其余交给 `refineSlide()`，按 `diff` 是否为空决定 toast `ai.intent.unknown` 还是成功文案。

`installIntentListener()` 幂等，重复安装只保留一个监听器。

## 8. 溯源与快照

`stampBlocks(blocks, { provider, model?, recipeId, promptDigest, at? })` 给每个块写：

- `provenance: { provider, model?, recipeId, promptDigest, at }`（`promptDigest = shortHash(prompt)`，10 位 base36）；
- `aiSnapshot`：**生成那一刻**的块 JSON（含 provenance、去掉 `aiSnapshot` 自身），超过 `SNAPSHOT_LIMIT = 120_000` 字符就不写。

schema 层 `aiSnapshot` 的上限是 400_000 字符（比生成端宽松，给导入的历史数据留余量）。UI 侧 `ProvenanceBadge` 消费这两个字段做"还原 AI 版本"。

## 9. ComposerPanel 结构

零 props 面板，`phase: 'idle' | 'outlining' | 'outline' | 'building' | 'done'` 一条线：

| 区块 | 内容 |
|---|---|
| 头部 | 标题 + 关闭（回到 `rightMode = 'inspector'`） |
| 通道徽标 | `channelInfo(llm)` → mock/endpoint；未就绪时给"去设置"链接与 mock 提示 |
| 提示词 | `TextArea`（`⌘/Ctrl+Enter` 触发生成） |
| 选项 | 听众、篇幅（short/normal/deep）、时长（5/10/20 分钟）、主题（同步写 `deckOps.setTheme`）、SVG/3D 开关 |
| 生成 | `composeOutline()`；`busy` 时禁用，`AbortController` 可取消 |
| 大纲 | `OutlineEditor`（可改可删可拖排）+ "逐幕成稿" |
| 进度 | `GenerationProgress(done,total)` + 取消 |
| 结果 | 成功 toast + warnings `<details>`（每条 `#n` 带单幕重试） |
| 微调 | `RefineBox`（自由指令 → patch plan → 应用） |

挂载时写 `document.documentElement.dataset.lumenAi = '1'` 并安装意图监听；错误统一经 `reasonOf()` 收敛成可读文案 + 重试按钮。

## 10. 已知限制

- Mock 是"确定性演示机"而非理解模型：换 prompt 只换语料包与种子，长尾需求会得到模板化文案（但永远可编辑、永远过 lint）。
- 修复环只回喂一次；复杂的结构错误（少字段、层级错）真端点可能两次都修不好，最终以 `badJson` 结束，用户看到的是"重试"。
- `RefineIntent` 里的 `rewrite` 只由 `buildByModel` 产出，`detectRefineIntent()` 永远不会返回它——规则表与类型不完全对称。
- `normalizeOutline()` 会**静默截断**到 20 幕、丢弃空要点、把超出预算的 3D 幕降为 `none`，用户在大纲里看不出被改过。
- 3D 预算（2 幕）在 `normalizeOutline` 与 `lint` 两处各有一份，改阈值要同时改。
- `translateText()` 只是 19 对词表，Mock 通道的"翻译"结果会很粗糙；真端点才走 LLM。
- `aiSnapshot` 是整块 JSON 字符串，块很大时会被 `SNAPSHOT_LIMIT` 跳过，"还原 AI 版本"对这类块不可用。
- 单幕生成并发固定 2：调大更快的代价是更容易撞上端点的 rate limit，且进度条与取消的体验会变差。
