# 02 架构设计 —— 模块边界、数据流与启动

> 本文只写**代码里实际存在的分层、单向依赖与数据流**，回答两个问题：这段逻辑该放哪、为什么它是这样组织的。
> 产品主张见 `doc/01-产品概述.md`，数据契约见 `doc/03-数据模型与DSL.md`，所有权与命令见 `doc/00-工程契约.md`。

## 1. 分层与模块图

```
┌────────────────────────────── App 外壳（src/App.tsx） ──────────────────────────────┐
│ TopBar · SlideRail · Stage · Inspector · Toasts · StudioHost · PrintHost · Dialogs  │
│ Player(mode='play' 时才挂载)                                                        │
└──────┬──────────────┬───────────────┬───────────────┬───────────────┬────────────────┘
       │              │               │               │               │
   editor/*        ai/*            play/*          ui/*          export/*
   (画布/面板)   (编排/配方)     (播放/讲者)    (基元/弹窗)     (HTML/PDF/PNG)
       │              │               │               │               │
       └──────────────┴───────┬───────┴───────────────┴───────────────┘
                              ▼
                        state/ops.ts            ← 唯一写入口
                              ▼
                    state/deckStore.ts          ← immer 补丁历史（200 步）
                              ▼
                     render/SlideRenderer       ← 唯一渲染入口（5 种 mode）
                              ▲
        themes/* · styles/tokens.css · assets/* · schema/*
```

**单向依赖**（用读码核对过，`render/**`、`schema/**`、`state/**` 都不反向引用上层）：

| 层 | 目录 | 允许依赖 | 不允许依赖 |
|---|---|---|---|
| 契约 | `src/schema/**` | zod、同层工具 | 任何运行时状态、React |
| 样式与主题 | `src/themes/**`、`src/styles/**` | `schema` | `state`、`render` |
| 渲染 | `src/render/**` | `schema`、`themes`、`i18n`、`assets` | `state`、`editor`、`ai` |
| 状态 | `src/state/**` | `schema`、`themes`（只读派生） | `render`、`editor`、`export` |
| 交互 | `src/editor/**` | `state`、`render`、`schema`、`i18n` | 直接改 deck 对象 |
| 编排 | `src/ai/**` | `schema`、`state.ops`、`themes`、`lint` | 自己排版 CSS |
| 输出 | `src/play/**`、`src/export/**` | `render`、`schema`、`themes`、`assets` | 改写 deck |

`src/lint/**` 是横切层：它只 import 了 `render/text/markdown` 的纯函数 `plainText()`，不碰 React 与 store，因此可以在导出、AI 配方、检查器三处复用同一个尺子。

## 3. 数据流：交互 → ops → 补丁 → 渲染

一条拖拽从指针到像素只走一条路，**没有组件直接改 deck 对象**：

```ts
// 1. 指针（src/editor/stage/useStageInteraction.ts）——rAF 合帧，一帧最多一次写库
const snapped = snapMove(moved, drag.lines, { threshold: 6, grid: GRID })

// 2. 唯一写入口（src/state/ops.ts）
blockOps.setGeometry(updates, { coalesceKey: 'drag' })

// 3. 补丁历史（src/state/deckStore.ts）
const [next, patches, inverse] = produceWithPatches(state.deck, (draft) => {
  recipe(draft)
  draft.meta.updatedAt = Date.now()
})
// coalesceKey 相同且在 650ms 内 → 合并进上一笔；patches 为空 → 直接返回，不产生历史

// 4. 订阅重渲染（src/render/SlideRenderer.tsx）
const blocks = [...slide.blocks].filter((b) => !b.hidden).sort((a, b) => a.z - b.z)
```

要点：

- 历史是**补丁对**（`patches` / `inverse`），不是快照；`HISTORY_LIMIT = 200`，`COALESCE_MS = 650`。
- 复合操作（多块插入、复制、AI 落稿）用 `transaction(label, fn)` 合成一步：`beginGroup` → 多次 `update` → `endGroup`。
- 一次性状态（选中、悬停、正在编辑的块）在 `selectionStore`，**不进历史**；`uiStore` 的 `zoom/activeSlideId/dialog` 同样不进。
- 拖动期间每帧写库是刻意的：几何真相只有一份（deck），覆盖层只保存参考线/角标这类视觉 ghost（见 `doc/04-编辑器.md` §1 与 §4）。

### 3.1 三个只读消费者

| 消费者 | 读什么 | 绝不做什么 |
|---|---|---|
| AI（`src/ai/**`） | `deck`、`getTheme()`、`lint` 的测量函数 | 不写 CSS、不产生 schema 之外的字段；落稿只经 `deckOps.applyOutline` / `blockOps.*` |
| 导出（`src/export/**`） | `deck`、`themeCssVars()`、`collectAssetDataUrls()` | 不改 deck；3D 取帧由导出层调 `captureThreeFrame()`，渲染层不往 deck 塞帧 |
| 播放（`src/play/**`） | `deck` + 本地 playback 状态 | 不改 deck；计时/黑屏/自动播放都在 `playbackCore` 的纯 reducer 里 |

### 3.2 一次 AI 落稿的路径

AI 的产物最终也必须落到同一个写入口，区别只是包了一层事务：

```ts
composeOutline(input)             // 提示 → Outline（schema/outlineSchema 形状）
  → buildDeckFromOutline(outline) // 逐幕跑配方，产出 Slide[]（块几何全部来自 recipes.ts）
  → deckOps.applyOutline(title, slides, { replace: true, prompt })
      └─ store.transaction('ai-apply-outline', () => {
           update(...)                       // 整盘替换 slides，单步撤销
           uiStore.setActiveSlide(first.id)  // 切到第一幕
           selectionStore.clearSelection()
         })
```

因此：**AI 与大模型无关地复用同一套几何与主题**，撤销一次就回到生成前；`provenance` / `aiSnapshot` 也是普通字段，跟着补丁一起被撤销（见 `doc/03-数据模型与DSL.md` §4.1 与 §8）。

## 4. 关键决策

| 决策 | 事实（代码位置） | 代价 |
|---|---|---|
| **单一渲染器** | `render/SlideRenderer.tsx` 是唯一入口，`mode: 'stage' \| 'play' \| 'thumb' \| 'print' \| 'export'` | 渲染层不能读状态，能力差异全由 `data-mode` CSS 与 props 分支承担 |
| **主题是 TS 数据** | `themes/index.ts` 的 `THEMES` → `themeCssVars()` → `--d-*`；导出序列化同一份 | 主题变量必须在运行时/导出时各注入一次；three 取色要另合并 `themeOverrides` |
| **补丁历史** | immer `produceWithPatches` + `applyPatches` | 依赖 immer 补丁语义；`setAutoFreeze(false)` 后靠 ops 与类型约束 |
| **资产不入 deck** | `image.assetId` 只是引用，数据在 IndexedDB（`assets/assetStore.ts`） | 导出/交换必须打包：`.lumen.json` 内联 dataURL，独立 HTML 内联素材 |
| **播放器独立构建** | `vite.player.config.ts` 产出 IIFE 内核到 `public/player/`，导出时内联 | 构建有先后：`predev`/`prebuild` 先跑 `scripts/build-player.mjs`；产物不入库 |
| **三类状态分离** | `deckStore`（历史）/ `uiStore`（外壳）/ `selectionStore`（选中） | 撤销不影响选中，切幕要显式清选择 |
| **结构而非截图** | `schema/deck.ts` 是唯一契约，AI 只产出 schema 内字段 | 排版能力全部压在 12 个配方里（`ai/recipes.ts`） |
| **渲染层无状态** | `render/**` 不 import `state/**` | 渲染层拿不到"谁被选中"，高亮只能由 `StageOverlay` 画 |

## 5. 启动流程

`src/main.tsx`：先 `await bootstrap()`，再挂 `createRoot`。CSS 顺序固定为 `tokens → base → primitives → slide.css → app.css`（后者可覆盖前者）。

`src/bootstrap.ts` 的六步，任何一步失败都降级到"可用的演示"，不留白屏：

```ts
1. loadSettings()            // 失败 → settings.hydrate(null) 用默认值，console.warn
2. startSettingsSync()       // 订阅设置 → <html data-ui-theme/lang/reduced-motion> + 400ms 防抖落库
3. loadDeck(lastDeckId)      // 没有 → listDeckSummaries()[0]（按 updatedAt 倒序）
4. 仍无 deck → createSampleDeck(lang)   // 失败 → uiStore.setBootError() → App 渲染错误页
5. setDeck(deck, { resetHistory: true }) + setActiveSlide(slides[0]) + setLastDeckId(deck.id)
6. saveDeck(deck) 然后 startAutosave()  // 800ms 防抖 + visibilitychange/beforeunload flush
```

- 历史从空开始：首次载入的 deck 不进撤销栈，用户第一次 `⌘Z` 不会把示例撤销掉。
- `persistence/kv.ts` 自己开 IndexedDB：**单库 `lumen-deck` v2**，一次 `upgrade` 建齐 `decks` / `assets` / `settings` 三个 object store。
  历史上用 idb-keyval 的 `createStore(db, name)` 只在**新建数据库**时才创建 store，第二个 store 在同一个库里并不存在 → `transaction` 抛 `NotFoundError` → 静默降级内存模式 → 刷新丢数据；现在改成自建开库，并把版本推到 2 以修复已损坏的 v1 库（`e2e/i18n.spec.ts` 的"刷新后仍是同一份演示"就是这条的回归）。
- 降级仍然保留：`indexedDB` 不可用（隐私模式 / 配额 / 测试环境）时整体退到内存 Map 并置 `storageMode = 'memory'`，`storageModeNotice()` 供 UI 提示。
- `bootError` 非空时 `App` 只渲染一段错误文本（品牌名 + 原因），不渲染工作台。

## 6. 跨模块协议

模块之间不互相 import 的耦合点，全部走这五个通道（改协议等于改契约）：

| 协议 | 方向 | 载荷 | 定义处 |
|---|---|---|---|
| `window` 事件 `lumen:intent` | 命令面板 → AI | `{ text, scope?: 'slide' \| 'deck' \| 'selection' }` | `ai/intent.ts` |
| `window` 事件 `lumen:open-studio` | 面板 → 工作室 | `{ kind: 'svg' \| 'three', blockId? }` | `studio/StudioHost.tsx` |
| `postMessage` `lumen:height` | HTML 块 iframe → 父页 | `{ type, height }`，父页先校验 `event.source` | `render/blocks/HtmlView.tsx` |
| `BroadcastChannel` `lumen-sync` | 主窗 ↔ 讲者窗 | `state` / `deck` / `command` / `hello` | `play/presenter.ts` |
| `document.documentElement.dataset.lumenStudio` | 工作室 → 面板 | `'1'` 表示监听已注册 | `studio/StudioHost.tsx` |

### 6.1 错误与提示约定

- 可恢复的失败（拖入不支持的文件、SVG 净化失败、AI 调用失败）一律 `uiStore.pushToast({ kind, message })`：`ttl` 默认 3200ms，列表最多保留 4 条。
- 不可恢复的失败（示例 deck 都生成不出来）才写 `bootError`，由外壳整页降级。
- `console.warn` 只用于"已降级"的诊断（IndexedDB 不可用、本地数据不符合 schema），不用于用户可见错误。
- AI 层把异常包成 `AiError`（带 `code`）再交给 UI，`isAborted()` 用于区分用户主动取消——取消不弹 toast。

## 8. 已知限制

- 补丁历史与 deck 结构强绑定：`schema/` 里新增字段若必须在 `ops` 里成对维护，否则撤销会漏字段（例如几何之外的派生量）。
- `themeOverrides` 只覆盖 7 个颜色键，字体/圆角/动效无法按 deck 覆盖，只能换主题。
- 状态分离带来一致性负担：删除块、切幕、导入 deck 都必须在 ops 里显式 `clearSelection()`，漏一处就会留下指向已删块的选中集。
- 跨模块协议是字符串事件名（`lumen:*`），没有类型安全的注册表；改名只能全局搜索。
- 导出与播放共用渲染器，但**播放器内核是另一份构建**（`src/player/entry.tsx`），渲染层任何改动都要重跑 `build:player` 才会进独立 HTML。
- 单测全部跑在 jsdom 下：没有真实布局、WebGL、IndexedDB，几何与渲染的断言只能到"结构/近似"级（真实像素靠截图 harness）。
- 采样数字（文件数、行数、用例数）随并行开发变动，以仓库现状为准。
