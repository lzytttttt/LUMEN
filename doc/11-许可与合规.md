# 11 许可与合规

> 本文回答"我能拿 LUMEN 做什么、不能做什么、商用怎么谈"。法律效力以根目录的
> `LICENSE`、`LICENSE-FSL-1.1-MIT.md`、`LICENSE-CC-BY-NC-4.0.txt` 原文为准；
> 面向使用者的完整导读见 [`../LICENSING.md`](../../LICENSING.md)，品牌规则见 [`../TRADEMARK.md`](../../TRADEMARK.md)。

## 1. 为什么从 CC BY-NC 4.0 迁移

`v0.2.0` 及更早版本使用 `CC BY-NC 4.0`。Creative Commons 官方不建议把 CC 协议用于软件：

- 没有专利授权条款，无法覆盖浏览器/播放器里用到的专利风险；
- 与 Apache-2.0 / MIT / GPL 等软件许可不兼容，下游无法安全地链接与再分发；
- "非商业"在软件分发、SaaS、内部计费等场景下边界模糊。

从 `v0.2.5` 起，源码改为 source-available 双轨授权；已发布版本的旧许可不追溯。

## 3. 默认路径：Apache-2.0 + Commons Clause

Commons Clause 只限制一件事：**不得转售本软件本身**（Sell the Software），包括把 LUMEN 或仅改名的等价物做成付费产品、付费 SaaS、付费模板包，或提供其托管服务并收费。

它不限制：自建、私有部署、内部培训、修改与衍生、嵌入更大的产品、咨询/实施/定制服务、非商业教学与研究。Apache-2.0 的专利授权与免责条款继续有效。

因此本项目**不是 OSI 开源**，请描述为 **source-available（源码可用）**。`package.json` 的 `license` 字段写作 `SEE LICENSE IN LICENSE`：SPDX 没有 `Apache-2.0 WITH Commons-Clause` 这样的标准表达式。

## 4. 备选路径：FSL-1.1-MIT

适合"法务要求明确的开源转化日期"的团队：

- 两年内不得做与本软件竞争的商业产品（Competing Use）；
- 内部使用、非商业教育/研究、围绕软件的 professional services 明确允许；
- 每个版本发布满两年后，该版本自动获得 MIT 许可（不可撤销）。

需要永久阻止"改名转售"时选默认路径；需要确定性转 MIT 时选 FSL。两者不叠加。

## 5. 分发与合规检查清单

发版前逐项确认：

- [ ] 仓库根目录的 `LICENSE`、`LICENSE-FSL-1.1-MIT.md`、`NOTICE`、`TRADEMARK.md` 均为最新；
- [ ] `package.json` 的 `license` 仍为 `SEE LICENSE IN LICENSE`，没有被 npm 初始化覆盖；
- [ ] 新增依赖的许可证与 `NOTICE` 不冲突；GPL/AGPL 依赖不得进入运行时；
- [ ] 导出的单文件 HTML 头部保留 LUMEN 版权与许可注释（`composeStandaloneHtml` 自动写入）；
- [ ] 示例文案、截图、品牌图没有被标成源码许可；
- [ ] `README` 与门户页的许可链接指向 `LICENSE` / `LICENSING.md`，不是 CC 协议主页；
- [ ] 商业授权咨询走 `lzytttttt@gmail.com`，不在公开 issue 里谈合同细节。

## 8. 常见问题

**Q：公司内部用它做周报/培训，要付费吗？**
A：不需要。默认路径允许内部使用与修改。

**Q：把它嵌进我们卖给客户的 SaaS，可以吗？**
A：可以，只要你卖的是你的产品，而不是 LUMEN 本身；不要再把 LUMEN 作为独立付费产品/模板包转售。

**Q：我们能改名为 "XX Presenter" 再发行吗？**
A：可以 fork 与改名，但必须去掉 LUMEN 品牌、保留版权与许可声明，且不得把改名版作为 LUMEN 的替代品转售。

**Q：示例文案能直接用于商业提案吗？**
A：示例文案/模板按 CC BY-NC 4.0，商用请替换为你自己的内容，或联系商业授权。

**Q：旧版本还能按 CC BY-NC 4.0 用吗？**
A：能。许可变更只影响变更后发布的版本。
