# 01 迭代计划 · v0.2.0

> 职责：把 `00` 的范围拆成 4 周、5 个里程碑、22 个可验收任务，给到文件级落点与人日估算。
> 上游：`00-范围与决策.md` · 下游：`02`–`09` 全部（每个任务都指向具体的规格文档）

---

## 1. 发布定位

| 项 | 内容 |
|---|---|
| 版本 | `0.1.0 → 0.2.0`（minor，因为新增了一整块用户可见能力且不破坏数据契约） |
| 一句话 | **LUMEN 有了自己的"生成界面"**：造幕台，可玩、会动、几乎不写字 |

| 不含 | 账号、云同步、协作、PPTX、视频、移动端（见 `00` §3.2） |

## 4. 预算冲突与砍法（评审必看）

31.7 人日 vs 22 人日预算，缺口 9.7。三个选项，建议选 **A**：

| 方案 | 做法 | 代价 | 结论 |
|---|---|---|---|
| **A 砍范围** | 把 T-11（游戏层）延到 v0.2.1，只保留"连击计数"这一个最小反馈；T-19 用样张代替真截图 | 成就/等级/解锁推迟；截图少 2 张 | **推荐**，v0.2.0 的卖点是造幕台本身，不是成就系统 |
| B 砍质量 | 不做 T-13 降级与无障碍、T-17 e2e | 低端机白屏风险 + 不可回归 | 否，这是产品化的底线 |
| C 加人 | 并行第二个前端 | 需要拆文件所有权，`src/forge/**` 与 `src/ai/**` 可分 | 可行，但协调成本约 1.5 人日 |

选 A 后的排期：**22 人日**，游戏层只保留 T-11a「连击计数 + 三个成就」，其余进 v0.2.1 backlog。

> 注意：`03-游戏化机制.md` 的完整设计**不删**，它同时是 v0.2.1 的规格。代码按"可开关"实现（`settings.forge.gameplay: 'min' | 'full'`），v0.2.1 只需翻开关 + 补 UI。两档**共用同一份 `ForgeProgress` 记录与同一套事件名**（`unlocks` / `gates` 字段先留空落库），为的是 v0.2.1 不用再做一次迁移——这条已由 `03` §7 确认。

## 5. 关键路径与并行泳道

```
W1  T-01 ─┬─ T-02 ─ T-04 ──────────────┐
           ├─ T-03 ─┬─ T-08 ────────┐   │
           └─ T-05 ─┴─ T-09 ─┬─ T-10 │   │
                              ├─ T-12 │   │
W2                            ├─ T-13 │   │
W3                            └─ T-18 │   │
W4  T-06/T-07（可提前）──────────────────┴─ T-16 ─ T-17 ─ T-20 ─ T-22
```

- **并行点 1**：T-05（配方补 enter）与 T-06/T-07（Seed/Deal）无依赖，可同人交替做，避免等 T-02。
- **并行点 2**：T-03（通道）与 T-09（台面）互不相干，可拆给第二人。
- **串行瓶颈**：T-08 → T-09 → T-10/T-12/T-13 全挂在"台面"上。台面一旦延期，W3 整周风险。缓解：T-09 先做 L1（纯 CSS），L3 环境粒子后置。
