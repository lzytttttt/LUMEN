# 02 造幕台 —— 界面与交互

> 职责：定义「造幕台（Forge）」这块整屏生成界面的**空间、状态、交互、数据契约与边界**。
> 上游：`00-范围与决策.md`（D1–D12、术语、档位、文案硬规则） · 数值见 `03-游戏化机制.md` · 动效见 `04-动效与流程可视化.md` · 通道见 `05-LLM接入规格.md`
> 下游：`07-验收与测试矩阵.md`（AS-xx 编号即验收项来源）

---

## 1. 它要解决什么

v0.1.0 的生成入口是右栏一张表单：6 个选项、4 行提示词、一个 4px 进度条。信息齐全，但**没有任何一刻让人想再试一次**。造幕台换三件事：

| 换掉 | 换成 | 为什么 |
|---|---|---|
| 表单 + 选项文字 | 一句话 + 3 组图标刻度 | 打字本身就是最强的输入 |
| 进度条 | 段落可视化：真实块在台面上落位 | 进度条只说明"在等"，落位说明"在成" |
| 完成 toast | 过检仪式 + 开演按钮 | 完成的瞬间要有价格感，才值得再开一套 |

**三条反目标**（写下来是为了防止评审时被"加个说明吧"拉回去）：

1. 不做向导/GPT 式对话气泡——用户不是来聊天的，是来做演示的。
2. 不做步骤条 + 步骤文字（"第 1 步：输入主题"）——状态由空间位置与动效表达。
3. 不做"AI 思考中…"这类无信息的等待态——每一毫秒都有可见的进展对象。

## 2. 入口与退出

### 2.1 入口（4 个，全部走同一个事件）

```ts
// src/forge/ForgeHost.tsx
export const FORGE_EVENT = 'lumen:open-forge'
window.dispatchEvent(new CustomEvent(FORGE_EVENT, { detail: { source: 'topbar' | 'palette' | 'rail' | 'empty' } }))
```

| 入口 | 位置 | 备注 |
|---|---|---|
| 主按钮 | 顶栏「生成」 | v0.1.0 的 `rightMode='composer'` 改为打开造幕台 |
| 命令面板 | `⌘K` → `forge.open` | 命令注册表已有注册模式（`commandRegistry.ts`） |
| 空工程 | 画布中央空态 | 首次打开零幕时显示 |
| 幕栏「+」 | 长按 400ms 出菜单 | 短按仍是"新建空白幕" |

挂载沿用 `StudioHost` 的两条硬要求（`session === null` 零渲染、`data-lumen-forge='1'`），并同时写 `uiStore.mode='forge'`，使顶栏/快捷键在造幕台期间让位（`mode` 联合类型扩为 `'edit' | 'preview' | 'play' | 'forge'`）。

### 2.2 退出语义（D12）

| 退出方式 | 结果 |
|---|---|
| `Esc` / 左上返回 | 若有 ≥1 幕已完成 → **立即**以一次事务 `deckOps.applyOutline(title, doneSlides, { replace: true, prompt })` 落库，回编辑器并选中第 1 幕；0 幕完成 → 原 deck 不动 |
| 生成中点「停」 | 已完成的幕保留（同上），剩余幕标 `dropped`，在幕栏里以虚线占位显示一次（可点「续上」重进造幕台） |
| 完成态点「播放」 | 落库后 `setMode('play')`，造幕台收起（不卸载 DOM，留 220ms 做交叉淡出） |
| 完成态点「回编辑器」 | 落库后收起（样张里这一项显示「回门户」，见 §2.4） |
| 浏览器刷新 | 未落库的部分丢失；`forgeDraft`（§7.2）保留提示条「续上一套」 |

> 落库纪律：中途退出**只写已完成的幕**，不写半成品幕；幂等——重复退出不产生第二次事务。

### 2.4 门户（Portal，样张层）

样张里有第三张页面 `mock/portal.html`：品牌 + 版本 + 「设置」+ 一句话主张 + 「进入工作台」+ 三张幕的扇形预览。**它不是 v0.2.0 的产品面**，定位是「造幕台入口转场的可视化证明」，理由写在 `04` §12.5。

| 项 | v0.2.0 的承诺 | 样张演到什么程度 |
|---|---|---|
| 入口 | 顶栏「生成」/ 命令面板 / 空工程态 / 幕栏「+」四处（§2.1） | 门户「进入工作台」是最像真入口的那一个 |
| 退出 | 回编辑器画布（`setMode('edit')`） | 显示「回门户」，因为样张的上一级就是门户 |
| 设置 | 全部落在现有 `SettingsDialog`（通道 / 模型 / 台面档位 / 声音 / 减少动效 / 语言） | 抽屉里改完写 `lumen.prefs`，造幕台启动读取 `tier` 与 `audio` |
| 转场 | 沿用 §2.2 的 220ms 交叉淡出 | `04` §8.4 的「三张卡归位 → 标题淡出 → 整页淡出 560ms」 |
| 不做 | 不做账号、最近项目、云同步（`00` §3.2 不变） | —— |

> 结论：门户作为**独立首页**列入 v0.2.1 候选；v0.2.0 只保证「从任意入口进造幕台」与「设置项一致」两件事。评审若要提前，`04` §12.5 的区块表已可直接当需求。

## 3. 空间与层级

### 3.1 三层结构

```
┌──────────────────────────────────────────────────────────────┐
│ HUD   ← 退出 / 标题 / 计数 3/9 / 连击 ×4 / 等级点              │  56px
│                                                              │
│          LAYER A 舞台（Seed 输入 / 卡阵 / 台面 / 开演席）        │
│                        1180 × 620 居中                        │
│                                                              │
│ LAYER C 瞬时反馈（连击脉冲 / 成就 / 错误气泡）——不占布局         │
│ HUD   ← Pulse 七阶段 · 3 组刻度 · 主按钮（生成大纲 / 开始生成 / 播放）│  72px
└──────────────────────────────────────────────────────────────┘
```

- 全屏 `position: fixed; inset: 0`，背景 `var(--ui-bg)` + 一层极淡径向光（`radial-gradient` at 50% 42%，`--ui-accent` 6%）。
- 舞台区按 `min(100vw - 80px, 1180px) × min(100vh - 168px, 620px)` 适配；1280 宽时舞台降到 1000×525，HUD 不变。
- 不使用滚动条；任何超出的内容属于设计错误。

### 3.2 HUD 只放 4 个对象

| 对象 | 内容 | 文字量 |
|---|---|---|
| 左 | ← 返回箭头 | 0 |
| 中 | 演示标题（生成后才有，等宽小字，超出省略） | 1 块 |
| 右 | `3/9` 计数 · `×4` 连击 · 等级点 | 3 块 |
| 底 | Pulse 七阶段 + 3 组刻度 + 主按钮 | 见 §8 |

HUD 不使用卡片、不描边，只有 1px 分隔线与 4% 透明底，保证"舞台是唯一主角"。

### 3.3 一处 3D，仅一处

装台台面是唯一带透视的空间（`perspective: 1600px`）。它的对象是**真实 DOM 幻灯片**（800×450 缩放的 `SlideRenderer` 输出），不是 three 纹理：

| 方案 | 文字清晰度 | 纹理成本 | 结论 |
|---|---|---|---|
| 幻灯片刻成纹理会 three | 缩放后发虚 | 每幕 1 张 2048×1152 ≈ 9MB 显存 | 否 |
| **DOM + CSS 3D 变换** | 原生矢量，任意缩放都锐 | 0 | **是** |
| WebGL 渲染文字 | 需 SDF 字体图集 | 高 | 否 |

three 在 L3 只做**环境粒子与光晕**（可选、可关、lazy），不承担信息呈现。这条决定写在此处，`04` 的所有 3D 动效都必须遵守。

## 4. 状态机

### 4.1 两个正交维度

```ts
type ForgePhase = 'seed' | 'deal' | 'casting' | 'premiere' | 'closing'

type SlideStatus =
  | 'queued'      // 已在大纲里，未开始
  | 'drafting'    // 正在出文案（对应 SLIDE_SYSTEM）
  | 'art'         // 正在出视觉（SVG / three）
  | 'typesetting' // 配方排版中（同步，通常 <16ms）
  | 'gating'      // lint 中（同步）
  | 'landed'      // 已落位
  | 'flagged'     // 落位但有 warn
  | 'stuck'       // lint error 且兜底仍失败 → 等「重试」
  | 'dropped'     // 用户中途停止
```

### 4.2 合法转移

| From | To | 触发 | 动效钩子（交给 `04`） |
|---|---|---|---|
| `seed` | `deal` | `composeOutline()` 成功 | `fx.deal` |
| `seed` | `seed` | 大纲失败 / 用户取消 | `fx.seedShake` |
| `deal` | `deal` | 换卡、拖排、删幕 | `fx.cardSwap` |
| `deal` | `casting` | 点「开始生成」/ `Enter` | `fx.curtain` |
| `casting` | `premiere` | 最后一幕 `landed` | `fx.tiltUp` |
| `casting` | `deal` | 全部 `dropped` 或全 `stuck` 且用户退出铸造 | `fx.cardsBack` |
| `premiere` | `closing` | 「回编辑器」/ `Esc` | `fx.fold` |
| `premiere` | `play` | 「播放」 | 交给 `play/transitions.css` |

单幕推进（`casting` 内部，由 `ForgeStageEvent` 驱动）：

```
queued ──slide:start──▶ drafting ──slide:content──▶ art ──slide:visual──▶
typesetting ──slide:layout──▶ gating ──slide:gate──▶ landed | flagged | stuck
```

`stuck` 可由「重试」回到 `drafting`（复用 `rebuildOutlineSlide`，只重跑这一幕）。

### 4.3 数据从哪来（唯一真相）

管线目前只有 `onProgress(done,total)`，造幕台需要更细的阶段性事件。v0.2.0 对 `src/ai/compose.ts` 做**纯增量**扩展（老调用方不传即不变）：

```ts
export type ForgeStageEvent =
  | { type: 'slide:start';    index: number }
  | { type: 'slide:content';  index: number; tokens: number }
  | { type: 'slide:visual';   index: number; kind: 'svg' | 'three' | 'none' }
  | { type: 'slide:layout';   index: number; blocks: number }
  | { type: 'slide:gate';     index: number; errors: string[]; warns: string[] }
  | { type: 'slide:landed';   index: number; slide: Slide }
  | { type: 'deck:done';      deck: Deck; warnings: string[] }

// BuildDeckOptions 增加：
onStage?: (event: ForgeStageEvent) => void
```

约束：

1. 事件在**该步骤完成的同一帧**发出，不预发、不延时，保证动效与真相同步（D2）。
2. `slide:layout` 与 `slide:gate` 是同步阶段，允许同一帧连发两条。
3. 造幕台内部维护 `slides: Slide[]`（自己就是真相），**不依赖** deckStore 的中途状态；落库只在退出时发生（§2.2）。
4. `isAborted` 时不发 `deck:done`，改发 `{ type: 'deck:aborted' }`（新增一条，供 `dropped` 收尾）。

## 5. 五段逐段规格

### 5.1 输入（`seed`）

```
                    （空，只有一行缓慢呼吸的插入符）

         ┌────────────────────────────────────────────┐
         │  给设计团队讲：为什么演示该换成 HTML           │   ← 唯一的大字
         └────────────────────────────────────────────┘

              ⌜换一套载体⌟  ⌜讲一次复盘⌟  ⌜课程大纲⌟      ← 3 张示例卡（≤6 字）

   [6 9 12]        [5′ 10′ 20′]        [◧ 视觉] [◈ 3D]            ← 3 组刻度，右下
                                                        「生成大纲」  ← 主按钮
```

| 项 | 规格 |
|---|---|
| 大字行 | 字号 56/64（随字数 42–64 自适应），居中，无边框无底色；`Enter` 提交，`Shift+Enter` 不换行（禁止多行） |
| 示例卡 | 3 张，来自 `corpus.ts` 的 4 意图语料（launch/plan/course/retro）各取一条，**点击即填入**（不自动提交）；悬停时整张卡轻微上浮 2px |
| 幕数刻度 | 6 / 9 / 12，对应 `length: short/normal/deep`；默认 9 常亮 |
| 时长刻度 | `5′ / 10′ / 20′`；默认 10′ |
| 视觉开关 | 两枚图标（SVG / 3D），默认开；关掉时对应视觉降为 `none`（等价 `includeSvg/include3d=false`） |
| 主按钮 | 「生成大纲」（英文 `Deal`），禁用态仅降低到 40% 透明度，不灰掉、不弹提示 |
| 空输入按 Enter | 输入行做一次 1px 横向抖动（120ms），不出现任何文字 |
| 已有草稿 | 底上一行残影按钮「续上一套」（≤5 字），点击恢复 `forgeDraft` |

**文字块计数**：大字输入(1) + 示例组(1) + 幕数组(1) + 时长组(1) + 主按钮(1) + 视觉开关组(1) = **6**，正好用满预算。

数据流：`composeOutline({ prompt, lang, audience: undefined, length, durationMin, includeSvg, include3d, themeId })`。造幕台不暴露「听众」输入框（v0.1.0 的表单项），改为在提示词里自然表达；这是刻意的减法。

### 5.2 大纲（`deal`）

大纲回来后，把 `outline.slides[]` 摊成卡阵。**一屏看完，不滚动**：3–12 幕用 **4 列 × 3 行**（卡 168×224）；13–20 幕用紧凑档 **5 列 × 4 行 = 20 位**（卡 190×168，缩略区 190×107），`normalizeOutline` 的上限正是 20，不多不少。两档总尺寸 714×700 与 998×708，都落在 1360×708 安全区内（断言见 `04` §6.1）。

```
┌──────┐┌──────┐┌──────┐┌──────┐
│ ▤▤▤  ││ ▤ ▤  ││ ▤━▤  ││ ▤▤▤  │   卡面 168×224：上 168×95 配方剪影（块几何投影，不画字）
│ 启幕 ││ 数据 ││时间轴││ 对开 │   下 130 信息区：卡名(≤4字) + 标题(≤12字) + 稀有度点 + 右下 #3
└──────┘└──────┘└──────┘└──────┘   剪影与卡名的字典在 03 §2.2 第 9 列
```

卡面的**权威定义在 `03` §2.2–2.4**：剪影不是随手画的图标，而是每个配方**块几何的投影**（形态词典逐条给定，`04` §6.3 给绘制语言）。造幕台**不 import `recipes.ts`**——卡面零排版成本、首帧即出，这是一条性能决定，也是 `03` 选字形而非真块缩略的原因。

| 交互 | 行为 | 键盘 |
|---|---|---|
| 悬停卡 | 抬升 4px + 边框转 `--ui-accent-line` | — |
| 点卡 | 展开 12 配方选择环（本卡周围 240ms 展开），选中即换 recipe（**保留** headline/points） | `Enter` 打开 / `Esc` 收起 |
| 拖卡 | 重排；拖起时其余卡让位 16px | `Alt+↑/↓` 换位 |
| 卡右上 ✕ | 删幕（最小保留 3 幕，第 3 幕时 ✕ 消失，不弹提示） | `Del` |
| 底部「+」 | 在末尾补一幕（默认配方 `statement`，内容为空占位） | `N` |
| 主按钮 | 「开始生成」 | `Enter`（无焦点在卡上时） |

**首末锁**：`cover` 固定第 1 幕、`closing` 固定最后一幕——第 1/末张卡右上角显示锁形小图标，点它只弹配方环里的同类项，不能改成别的类别。依据：`normalizeOutline` 已按契约要求首末，UI 不给出违反契约的入口。

**换卡时的诚实**：`normalizeOutline` 会静默把超预算的 3D 幕降为 `none`（见 `doc/06` §10）。造幕台必须把它显性化——被降级的那张卡角标显示「无视觉」，点开配方环时该类配方置灰并标注原因码 `3d.budget`。这是对已知限制的正面处理，不是新增文案。

**文字块计数**：卡面（12 张同构，计 **1 组**：剪影不画字，只有卡名与序号）+ 主按钮(1) + 计数角标(1) = 3 组；卡面上的**标题是用户内容，按 §8 不计入系统文案预算**。

### 5.3 生成（`cast` + `assemble`）

这是造幕台的"哇"时刻，也是本文档最需要精确的一节。

#### 台面几何

```
            视野中心 (0,0)
   ┌──────────────────────────────────────────────┐
   │        ┌────────────────────────┐            │   ← 当前落位幕：真实幻灯片 DOM
   │        │  ┌──────────────────┐  │            │      800×450，perspective(1600px)
   │        │  │   headline        │  │            │      rotateX(6deg) rotateY(-10deg)
   │        │  │   ▁▁▁▁▁           │  │            │
   │        │  └──────────────────┘  │            │
   │        └────────────────────────┘            │
   │   ▤▤▤▤  ▤▤▤▤  ▤▤▤▤  ▤▤▤▤                     │   ← 已落位幕：左侧竖向叠放
   └──────────────────────────────────────────────┘      每张 160×90，z 轴阶梯 -40px
```

| 对象 | 尺寸 | 变换 | 说明 |
|---|---|---|---|
| 在铸幕 | 800×450 | `translateZ(0)`，落位后 `translateZ(400)→0` | 落位瞬间有 120ms 的"贴合"回弹 |
| 完成栈 | 每张 160×90，间距 12px | `rotateY(14deg)`，z 阶梯 | 最多同时显示 6 张，更早的淡出为一张「+3」纸角 |
| 光带 | 8px 高，贯穿舞台 | `mask` 渐隐 | 落位时扫过 1 次，520ms |

#### 落位动画就是真实入场动画（D2 的核心）

每一幕在 `slide:landed` 后，**按该幕真实块的 `enter` + `enterDelayMs` 逐块入场**：

| 真实字段 | 视觉结果 |
|---|---|
| `enter: 'rise'` | 块从 +24px 上浮到位，`cubic-bezier(.32,.72,0,1)`，420ms |
| `enter: 'fade'` | 透明度 0→1，320ms |
| `enter: 'scale'` | `scale(.94)→1`，360ms |
| `enter: 'none'` | 直接可见（不补假动画） |
| `enterDelayMs: 0–3000` | 原样作为 `animation-delay`，这正是 `timeline` 配方 70ms 错峰的来源 |

> 这条让"造幕台里看到的"与"播放时看到的"是同一套数据。用户学会的节奏，就是成品的节奏。

#### 文案的到达必须是流式的

真端点开流（`05` §3）时，`slide:content` 携带的 token 数用于驱动逐字写入：字符以 8–14ms/字 的速度落在标题位置，写完后再进入 `typesetting`。/ 回放（`replay`）用 fixture 里录好的 `delays[]`，Mock 用固定 110ms —— **三种通道的观感一致，节奏来源不同**。

#### 处理的并发与顺序

管线并发为 2（`runPool(slides, 2)`）。台面同时最多显示 **2 张在铸幕**（左右各一，z 轴错开 120px），完成即入栈。所以视觉上永远是"两幕并行落下"，与真实并发一致，不做假的单线程演出。

#### 中止

生成中点「停」：在铸的两幕 fade 到 30% 后消失，已完成栈整体下沉 40px 并变暗，Pulse 收缩为一条线，HUD 出现「续上」（复用 `forgeDraft`）。

### 5.4 检查（`gate`）

过检不是独立页面，而是**落位路径上的一道门**：在铸幕从 `translateZ(400)` 飞向 `0` 的途中穿过两道 1px 竖线（间距 160px）。

| lint 结果 | 视觉 | 交互 |
|---|---|---|
| 0 error 0 warn | 两道门亮起 `--ui-accent`，幕穿过时门与幕之间拉出一条 2px 金线（240ms），落位 | 无 |
| 有 warn | 门亮 `--ui-warn`，落位后右上角出现一枚 6px 琥珀星 | 点星展开 lint 码（如 `textOverflow`）与「重试」 |
| 有 error（且兜底后仍 error） | 幕**停在门中间**（`translateZ(200)`，`scale(.96)`），门变 `--ui-danger`，金星火花 1 次 | 幕下方只出现一个按钮「重试」；按 `R` 等效 |
| 重铸成功 | 门重新变金，幕继续飞入落位 | — |
| 重铸再失败 | 幕降为 `stuck` 并**允许带病落位**（半透明角标 `!`），绝不阻塞整场 | 星标可再次重铸 |

**绝不出现的东西**：红色弹窗、错误段落、"请检查…"的说明句。错误只有一个字级的承载体：门、星、`!`、以及一个按钮。

过检的判定完全来自现有 `lintDeck`（单幕探针，与 `compose.ts` 的 `slideIssues()` 同一把尺子），造幕台不新增规则。

### 5.5 播放（`premiere`）

最后一幕落位后 300ms：

1. 完成栈从左侧竖向排布 `rotateY(14deg)` 过渡为正面**一排 9 张**（`rotateY(0)`，`translateZ` 递减形成弧），400ms。
2. 灯光收束：舞台上方的径向光从 6% 提到 14%，其余 UI 降为 24% 不透明。
3. 主按钮从「开始生成」变为「播放」，按钮底色取当前 deck 封面幕的 `accent`（自指，很便宜但很好看）。
4. 下方一行残影操作：`回编辑器` / `再来一套`（≤5 字）。

点「播放」→ 落库 → `setMode('play')` → 造幕台做 220ms 交叉淡出，播放器从封面开始。转场沿用 `play/transitions.css` 的 5 种，不新增。

## 8. 文字预算实测表

计数规则：**系统文案**（界面语）里可独立识读的文本块计 1；同组标记（如 `6 9 12`、3 张示例卡）计 1 组。**用户自己的内容不计入**——输入的那句话、卡面标题、演示标题属于用户产出，不是"文字介绍"。

| 屏 | 文本块 | 明细 | 预算 |
|---|---|---|---|
| 起念 | 6 | 输入 / 示例组 / 幕数组 / 时长组 / 视觉开关组 / 「生成大纲」 | 6 ✅ |
| 抽幕 | 3 | 卡面组（剪影不画字，仅卡名+序号）/ 计数 / 「开始生成」 | 6 ✅ |
| 装台 | 3 | 计数 `3/9` / 连击 `×4` / 标题 | 6 ✅ |
| 过检 | +1 | 仅在有问题时出现「重试」 | 6 ✅ |
| 开演 | 3 | 「播放」/ 「回编辑器」/ 「再来一套」 | 6 ✅ |
| 错误态 | +2 | 气泡 ≤4 字 + 一个动词按钮 | 6 ✅ |

Pulse 的七阶段**不写字**，只用字形 + 明度；阶段含义见 `09-文案词表.md` 的"无字阶段"约定。

## 9. 无障碍与降级

### 9.1 键盘全流程

| 场景 | 键 | 行为 |
|---|---|---|
| 起念 | `Enter` | 提交 |
| 起念 | `Tab` | 焦点顺序：输入 → 示例组 → 幕数 → 时长 → 视觉 → 抽幕 |
| 抽幕 | `←/→` + `Enter` | 遍历卡并打开配方环 |
| 抽幕 | `Alt+↑/↓` | 换位 |
| 抽幕 | `Del` | 删幕（≥4 幕时可用） |
| 装台 | `R` | 对 `stuck` 幕重铸 |
| 全局 | `Esc` | 退出（语义见 §2.2） |
| 开演 | `Space` / `Enter` | 开演 |

焦点：造幕台是 `role="dialog" aria-modal="true"`，焦点陷阱 + 进入时落到输入框/首卡；`Esc` 后焦点回到触发按钮（记录在 `ForgeHost` 的 `returnFocus`）。

### 9.2 读屏

- 只有一个 `aria-live="polite"` 区域，**节流 ≥1.5s**，只播报三件事：阶段变化（"装台"）、完成（"9 幕完成"）、错误（"第 4 幕需重铸"）。
- 逐幕进度不播报（否则读屏被刷屏），改为 `role="progressbar"` 的 `aria-valuenow` 静默更新。
- 卡阵是 `role="listbox"` + 每卡 `role="option" aria-selected`；配方环是 `role="menu"`。

### 9.3 降级

| 档 | 触发 | 差异 |
|---|---|---|
| L3 | WebGL2 + 核数 ≥4 + 非省电 | 全动效 + 环境粒子 |
| L2 | 无 WebGL 或首帧 >32ms | 无粒子，保留 3D 透视 |
| L1 | `prefers-reduced-motion` / 核数 ≤2 / 省电 | 位移改为纯 opacity 120ms；不出现视差与光带 |
| L0 | 设置里锁定 / e2e 截图模式 | 状态瞬切，无过渡；用于视觉基线 |

降级只影响**表现**，不影响任何功能与可达性；L0 下所有交互仍完整可用。

## 10. 性能预算与实现要点

| 项 | 目标 | 实现要点 |
|---|---|---|
| 首屏可交互 | ≤400ms | 造幕台代码拆分（`React.lazy`），入口点击后预取；字体用系统栈 |
| 首屏 JS 增量 | ≤40KB gzip | 12 字形内联 SVG 合计 ≤14KB；动效用 CSS + 一个 400 行内的 rAF 调度器 |
| 落位动画 | 220–420ms，掉帧 ≤2 | 只用 `transform` / `opacity`；对在铸幕 `will-change: transform`，落位后**立即撤销** |
| 同时动画元素 | ≤24 | 在铸 2 幕 × (≤12 块) 上限 |
| three | 不首屏加载 | `await import('three')` 仅在 L3 且用户未关环境光时 |
| 内存 | 退出后回落 | 卸载时清空 `slides` 引用、移除 rAF、`releasePointerCapture` |
| 长任务 | 单帧 ≤50ms | 排版与 lint 都在管线里同步完成；造幕台只做 Diff 渲染，不做测量 |

反模式（明确禁止）：用 `setInterval` 驱动假进度、给整屏加 `backdrop-filter`、对 `box-shadow` 做动画、在 3D 场景里塞 DOM 之外的第二套幻灯片。

## 11. 错误与边界

| 情况 | 表现 | 退出路径 |
|---|---|---|
| 大纲 401/403 | 起念屏输入行下沉 2px，气泡「钥匙失效」+ 按钮「设置」 | 打开设置对话框，造幕台不关 |
| 429 | 气泡「太快了」+ 自动 1 次退避（`05` §6），按钮变「重试」 | 手动重试 |
| 网络断 | 气泡「断网了」 | 「重试」 |
| badJson（修复环用尽） | 气泡「重来一次」 | 「重试」（只重跑大纲） |
| 输出超 20 幕 | 抽幕阶段只渲染前 20 张，并在计数处显示 `20/20`（不弹提示，`normalizeOutline` 已截断） | — |
| 英文超长标题 | 卡面标题两行截断 + 省略号；装台幕内由配方字阶自适应接管（`TITLE_LADDER`） | — |
| 空输入提交 | 1px 抖动，无文字 | — |
| 重复提交 | 主按钮 `disabled` 且 `aria-disabled`，键盘 Enter 触发去重（同一 `AbortController` 复用） | — |
| 生成中关闭 | §2.2 | — |
| 撤销后重进 | `forgeDraft.done` 与实际 deck 不一致时以 deck 为准，草稿只作提示 | — |
