# 00 范围与决策

> 职责：本目录所有文档的共同前提——v0.2.0 要交付什么、边界在哪、哪些决定已经锁死。
> 其他文档只引用本文，不重复论证。**与本文冲突的内容按本文为准。**
> 上游：无 · 下游：`01`–`09` 全部。

---

## 1. 一句话

v0.2.0 = **产品化的一次正式发布**：把「右栏表单式生成」换成 **造幕台（Forge）**——一个整屏、可玩、动效驱动、几乎不写字的一键成幕体验；同时把 LLM 通道补到「真模型、可流式、可回放、可离线演示」的工程完成度。

本轮**只产出文档与样张**（`plan/v0.2.0/` 内），不改 `src/**`。实现按 `01-迭代计划.md` 分批落地。

## 2. 现状盘点（v0.1.0 已成立的事实）

| 能力 | 现状（代码事实） | v0.2.0 处置 |
|---|---|---|
| 编排管线 | `composeOutline()` → `buildDeckFromOutline()`，并发 2，单幕失败降级，一次事务落库 | **复用**，只加阶段回调（`onStage`），不改数据结构 |
| 生成入口 | `ai/ui/ComposerPanel.tsx` 右栏表单：徽标 / 提示词 / 6 项选项 / 大纲编辑 / 4px 进度条 | **新增造幕台为默认入口**；面板降级为「精确模式」保留 |
| 通道 | `MockProvider`（110ms 确定性）+ `OpenAICompatProvider`（非流式、无重试、无缓存） | **扩**：流式 SSE、退避重试、响应缓存、`replay` 回放通道、预设档 |
| 校验 | `parseWithRepair`（extractJson → zod → 一次修复回喂） | 保留；修复环提升为**过检仪式**的可视对象 |
| 质量门 | `lintDeck` 11 个 code，`error` 触发一次兜底重排 | 升级为**过检（Gate）**：error=卡住+火花，warn=瑕疵星标 |
| 排版 | `recipes.ts` 12 个配方，纯函数产出块；块自带 `enter` / `enterDelayMs` | **成为动效数据源**：装台动效不是假动画，是真实入场动画 |
| 视觉层 | `styles/tokens.css` 双主题 UI 令牌；deck 主题 `--d-*` 运行时注入 | 造幕台只用 UI 令牌，不引入新色 |
| 挂载 | `StudioHost`：`session===null` 零渲染 + `data-lumen-studio` 标记 | 造幕台照抄这个模式（`data-lumen-forge`） |
| 游戏层 | 无 | **新增**（纯本地、零阻塞） |
| 演示数据 | 9 幕示例 `sample-deck.ts` | 复用为「一键试玩」素材 |

**结论**：管线、契约、lint 都已具备，v0.2.0 的重心是**表现层与通道**，不是重写内核。这是本次迭代最大的风险控制点——`src/schema/**` 与 `src/state/**` 不应出现破坏性改动。

## 3. 边界

### 3.1 做（v0.2.0 范围内）

1. 造幕台整屏体验：**起念 → 抽幕 → 铸造·装台 → 过检 → 开演**（五段；铸造与装台同屏，所以对外只有 5 个阶段点，DOM 标记拆成 6 个值，见 `02` §4.4）。
2. 游戏化：幕卡、连击、熟练度、成就、开箱式解锁——全部本地、全部不阻塞功能。
3. 流程可视化：真实管线阶段（思考/写作/画图/排版/过检）映射为可看懂的动效，不写说明文字。
4. LLM 通道：流式、预设档（DeepSeek / OpenAI / Ollama / 自建网关 / 本模型）、重试与退避、缓存、`replay` 回放。
5. 用一个真实模型（本会话模型）跑通全流程并把产物固化成 trace，供离线演示与 e2e 使用。
6. 产品化要件：版本、变更日志、首启引导、截图重拍、无障碍与降级、性能预算。

### 3.2 不做（明确挡在门外）

| 不做 | 理由 |
|---|---|
| 账号、云同步、协作、评论 | 产品定位是「无后端、无遥测」，v0.2.0 不破 |
| 排行榜、分享到社交、多人竞技 | 游戏化只服务「自己做出一套好演示」，不做攀比 |
| 遥测、埋点、A/B 平台 | 同上；本地计数器写 IndexedDB，永不出网 |
| PPTX / Keynote 导出 | 需要服务端或重型库，v0.3 议题 |
| 视频导出（MP4/GIF） | 编码器体积与版权风险，先用单文件 HTML 替代 |
| AI 生成位图（文生图） | 与「无外链、离线可用」冲突 |
| 移动端布局 | 1600×900 画布 + 精修交互，v0.2.0 只承诺 ≥1280 宽桌面 |
| 独立门户首页（portal） | 样张已演（`04` §12.5、`02` §2.4），列入 v0.2.1 候选；v0.2.0 只保证"从任意入口进造幕台"与设置项一致 |
| 重构 `src/render/**` | 造幕台只消费渲染器，不改渲染契约 |

## 4. 已锁定的决策

| # | 决策 | 为什么（一句） |
|---|---|---|
| D1 | 造幕台是**整屏 overlay**，由 `uiStore.mode` 扩一个 `'forge'` 驱动，沿用 `StudioHost` 的零渲染模式 | 不打断编辑器状态机，关闭即回到画布，中途退出不丢已生成幕 |
| D2 | 一切动效**由真实数据驱动**（`block.enter` / `enterDelayMs` / `phase` / 真实 token 流），不允许纯装饰假进度 | 用户看到的就是最终效果，减少"演示很炫、结果很丑"的落差 |
| D3 | 装台（3D 台面）默认开，性能不足自动降级到 L1，可在设置里锁档 | 3D 是产品身份，但不能让低端机卡死 |
| D4 | 游戏层**零阻塞**：等级、成就、连击都不解锁功能、不限制次数、不制造稀缺 | 演示工具的用户是来干活的，被游戏卡住会立刻卸载 |
| D5 | **文字预算**：造幕台单屏 ≤ 6 个文字元素；按钮 ≤ 3 字；标签 ≤ 6 字；唯一的长句是用户自己输入的那句话 | 「不出现繁琐的文字介绍」是本轮硬需求 |
| D6 | 音效默认**关**，开启后仅 5 类轻音（抽卡/落位/过检/连击/开演），音量 ≤ -18LUFS | 浏览器自动播放策略 + 观感清新 |
| D7 | 无排行榜、无社交、无遥测；成就与等级只写本地 | 定位与合规成本 |
| D8 | 真端点默认**流式**；Mock 保持非流式（确定性优先）；`replay` 走录制好的流帧 | 流式是动效的真实燃料，Mock 的确定性是测试的地基 |
| D9 | `replay` 通道是离线演示与 e2e 的**唯一真相**，fixtures 放 `plan/v0.2.0/assets/` 与 `fixtures/` | 无网络也能复现同一套产物 |
| D10 | 文案中英键必须**对等**（同 `src/i18n` 现有约束），字数上限两边各自成立 | 现有 i18n 测试会挂 |
| D11 | **不新增运行时依赖**；动效用 CSS 变量 + Web Animations API + 一颗自写 rAF 调度器 | 包体预算与"无外链"承诺 |
| D12 | 造幕台随时可关闭；关闭时把已完成的幕**立刻**落库（不等到最后） | 「跑到一半想看看」是真实行为 |
| D13 | **界面词与内部代号分离**：代号（起念/抽幕/铸造·装台/过检/重铸/开演）只用于文档、i18n key、事件名与 `data-forge` 值；**界面上不出现任何代号**，一律用大白话（输入/大纲/生成/检查/播放 + 生成大纲/开始生成/重试/播放） | 「开铸」对第一次用的人不成立，代号是给团队沟通的，不是给用户读的 |

## 5. 术语表（代号 + 界面词 + 代码标识）

三列缺一不可：**代号**用于文档与团队沟通，**界面词**是用户唯一看得到的说法（D13），**代码标识**永远是英文小写（i18n key、事件名、`data-forge` 值）。

| 代号 | 界面词 | 代码标识 | 含义 |
|---|---|---|---|
| 造幕台 | （不出现）工作台 | `forge` | 整屏生成体验的容器 |
| 起念 | **输入** | `seed` | 输入一句话的场景 |
| 幕卡 | **卡**（无独立界面词） | `card` | 一个 `RecipeId` 的可视化卡面 |
| 抽幕 | **大纲** | `deal` | 大纲返回后把配方摊成卡面 |
| 铸造 | **生成**（与装台同屏） | `cast` | 逐幕成稿（文案 + 视觉 + 排版） |
| 装台 | **生成** | `assemble` | 完成的一幕落到台面 |
| 过检 | **检查** | `gate` | `lintDeck` 结果的可视化质量门 |
| 重铸 | **重试** | `recast` | 单幕重建（复用 `rebuildOutlineSlide`） |
| 开演 | **播放** | `premiere` | 从造幕台直接进全屏播放 |
| 连击 | **连击** | `combo` | 连续有效操作计数 |
| 熟练度 | **等级** | `mastery` | 本地等级，只解锁皮肤/快捷方式 |
| 流程脉冲 | （不出现） | `pulse` | 管线阶段指示器，只画字形不写字 |
| 降级档 | （不出现）台面档位 | `tier` | 性能档位 L0–L3 |

主按钮的界面词（`09` 是唯一真相）：`生成大纲` · `开始生成` · `重试` · `播放`。

> 改词纪律：**改界面词只改 `09`**；改代号要同时改 `02`/`03`/`04`/`07` 与本文。两套词混用算缺陷，`07` 的 A 组用例会抓。

英文界面里这四个词就是 **Seed / Deal / Cast / Gate / Premiere**（动作名，直接当按钮标签，天然 ≤ 8 字符）。

## 6. 性能与降级

### 6.1 档位

| 档 | 判定 | 装台表现 | 其它 |
|---|---|---|---|
| **L3** WebGL | `webgl2` 可用且 `hardwareConcurrency ≥ 4`，非 `saveData` | three 台面 + 景深微光 | 全动效 |
| **L2** Canvas2D | 无 WebGL 或首帧 > 32ms | 2.5D 平行四边形台面（canvas 绘制） | 全动效，去掉景深 |
| **L1** CSS only | `prefers-reduced-motion`、`hardwareConcurrency ≤ 2`、或开启省电 | DOM + `transform` 卡片流水线 | 保留位移与淡入，去掉粒子/模糊 |
| **L0** 静态 | 用户显式开启「极简」或 e2e 截图模式 | 无动画，直接切图 | 用于快照与低端 kiosk |

降级**只降不升**（一次判定，运行中不反复抖动），判定结果写 `forge.tier` 并可在设置里锁定。

### 6.2 预算（可测）

| 指标 | 目标 | 测法 |
|---|---|---|
| 造幕台首屏可交互 | ≤ 400ms | Playwright `performance.mark` |
| 装台单幕落位动画 | 220–420ms，掉帧 ≤ 2 | **口径 = 卡面运动**（不含块入场），rAF 采样 P95 帧间隔 ≤ 20ms |
| 首屏 JS 增量 | ≤ 40KB gzip（不含 three） | `vite build` 产物对比 v0.1.0 |
| three 分块 | 必须 lazy，且不在首屏请求 | Network 面板断言 |
| 长任务 | 单帧 ≤ 50ms | PerformanceObserver `longtask` |
| 内存 | 装台结束后释台面纹理（`dispose`） | DevTools Memory 前后差 ≤ 30MB |

## 7. 文案与观感硬规则

1. **一个屏幕只说一件事**：造幕台任何时刻 ≤ 6 个**系统文案**文字元素（含按钮标签）。**用户自己的内容不计入**——输入的那句话、卡面标题、演示标题都是用户产出，不是"文字介绍"。
2. **不用解释性长句**：功能说明最多 6 个汉字或 1 个英文词；不写「系统将为你…」。
3. **动词优先**：一枚主按钮只有一个动词，随阶段推进更换——输入「生成大纲」→ 大纲「开始生成」→ 检查「重试」→ 播放「播放」；不用「确定/取消」。按钮最长 4 字，「生成大纲」「开始生成」是上限。
4. **数字即文案**：`3/9`、`×4`、`+12` 这种计数器本身就是信息，不配说明。
5. **错误短句化**：≤ 6 字 + 一个动词按钮（例：「太快了 · 重试」）。
6. **不出现感叹号**、不出现「AI 正在为你努力」类拟人抒情。
7. **中英等长**：同一 key 中英长度差 ≤ 1.6×，超出就换词。
8. 术语统一按 §5，不出现「幻灯片/PPT/生成器」等混称。

文案全表见 `09-文案词表.md`。

## 8. 文档地图与写作规则

| 文档 | 回答什么问题 |
|---|---|
| `01-迭代计划.md` | 4 周怎么排、谁做什么、什么算完成、什么时候打 tag |
| `02-造幕台-界面与交互.md` | 屏幕长什么样、状态怎么走、点了发生什么、键盘与无障碍 |
| `03-游戏化机制.md` | 卡面/连击/熟练度/成就的具体数值与防挫败设计 |
| `04-动效与流程可视化.md` | 每个动效的关键帧、时长、缓动、数据来源与降级 |
| `05-LLM接入规格.md` | 通道怎么扩、流式协议、错误映射、预算成本、密钥与 CORS |
| `06-端到端模拟跑通.md` | 一次真实模型跑完的证据：请求、响应、产物、校验、耗时 |
| `07-验收与测试矩阵.md` | 每条能力怎么验、用什么工具、通过标准 |
| `08-发布清单.md` | 发版当天按什么顺序做什么、怎么回滚 |
| `09-文案词表.md` | 界面上每一句中文/英文、字数上限、禁用词 |

写作规则（所有文档）：

- **表格优先**，散文只用来解释「为什么」，单个论点 ≤ 2 句。
- 一切数值（毫秒、KB、token、字数）必须可量测或可核对；拍脑袋的数标 `待测`。
- 代码块只放**契约**（类型、事件名、请求体、动画关键帧），不放完整实现。
- 每个设计点写清「数据从哪来」，避免出现凭空捏造的动效。
- 每篇末尾保留 `## 未决` 小节，列真实待评审项；没有就写「无」。
