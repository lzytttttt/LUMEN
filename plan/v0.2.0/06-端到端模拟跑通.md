### 4.2 单幕（`data` 幕的答复）

```json
{
  "headline": "三个指标同时转好",
  "lead": "口径：试点 6 个团队，12 周",
```

### 4.3 视觉（一次 SVG + 一次 three）

SVG 遵守 `SVG_SYSTEM` 的全部约束：820×560、只用 `var(--d-*)` 令牌、无 `<text>`、无 `<style>`、无事件属性。three 只产出受限描述符：

```json
{ "descriptor": { "preset": "particle-cloud", "palette": "duotone", "light": "neon",
  "bg": "transparent", "camera": { "distance": 8.4, "elevation": 0.24, "fov": 42 },
  "motion": { "kind": "rotate", "speed": 0.34 }, "objects": [], "grain": 0.06,
  "orbitControls": false } }
```

`objects: []` 是刻意的：`particle-cloud` 预设自己生成粒子，多写反而超预算。

## 7. 指标与两个真实发现

### 7.1 为什么 `data` 21 块不算问题

`data` 配方的结构性开销是真实的：4 组柱状条（shape）+ 环形图（SVG 弧段）+ 结论标题 + lead + 分隔线 + 「示意数据」脚注 = 21 个块。`LINT_LIMITS.maxBlocksPerSlide = 18` 是给**人工堆块**设的上限，配方产物天然更碎。

结论：不改阈值，改**归类**——`tooManyBlocks` 对"配方生成的幕"应当降为 `info` 且默认不展示（造幕台的星标只认 `warn` 与 `error`）。这条写进 `04` 的过检表与 `07` 的验收项。

### 7.2 token 与成本（实测字符 + 估算 token）

先测字符（可核对：`assets/trace-prompts.json` / `trace-model-responses.json` 的实际长度）：

| 项 | 字符数 | 其中 CJK+全角标点 | 其中 ASCII/其它 |
|---|---|---|---|
| 10 条 prompt（1 大纲 + 9 单幕） | 12 269 | 5 204 | 7 065 |
| 模型答复（大纲 + 9 幕 + SVG + three） | 4 258 | 1 042 | 3 216 |

token 用两种口径换算，**取 CJK 感知的那一档为准**：

| 口径 | 输入 | 输出 | 说明 |
|---|---|---|---|
| 代码里的 `estimateTokens = len/4` | 3 068 | 1 065 | 对中文严重低估（约 2.2×） |
| **CJK 感知：`cjk×0.95 + other/4`** | **6 710** | **1 794** | 10 条实测；再加 SVG/three 两条视觉请求约 0.7k → 输入 ≈ **7.4k** |
| 合计 | ≈ **9.2k** | — | 12 次请求 / 套 |

成本按 `05` §9.3 的两档价目代入即可（该表单价标 `待复核`，未联网自证）：

```
经济档  ¥0.5/M 入 · ¥2/M 出   → 7.4×0.0005 + 1.8×0.002  ≈ ¥0.007
能力档  ¥20/M 入 · ¥60/M 出   → 7.4×0.020  + 1.8×0.060  ≈ ¥0.26
```

结论：**一套 9 幕的成本在 1 分～3 毛之间**，取决于档位。无论哪档，"重铸"都可以做成零冷却——这是 `03` 敢把连击做成无惩罚的前提。

> 口径差异说明：`05` §9 的表用 6.9k/4.4k，输入与本节同源（1670 字符 ≈ 707 tok 即其系数），输出偏高是因为把 SVG 源码按整段计入。**以本节实测为准**，`05` 的单价不变。另：`estimateTokens` 的中文低估建议在 `05` 的缓存/预算里换掉，否则界面上的"用量"会小 2 倍。

### 7.3 发现一：`enter` 覆盖率 35.7%（必须修）

| 幕 | 配方 | 块数 | 带 `enter` 的块 | 覆盖率 |
|---|---|---|---|---|
| 1 | cover | 6 | 0 | 0% |
| 2 | statement | 3 | 0 | 0% |
| 3 | data | 21 | 8 | 38% |
| 4 | timeline | 15 | 9 | 60% |
| 5 | split | 8 | 0 | 0% |
| 6 | grid3 | 15 | 9 | 60% |
| 7 | compare | 10 | 4 | 40% |
| 8 | quote | 3 | 0 | 0% |
| 9 | closing | 3 | 0 | 0% |
| **计** | 9 配方 | **84** | **30** | **35.7%** |

影响很直接：`02` §5.3 规定"装台落位动画直接复用真实 `enter`/`enterDelayMs`"（D2）。按当前数据，**9 幕里有 5 幕没有块级入场动效**，装台会在这些幕上退化成"整体一贴"，那就变成了假动画——正好违反 D2。

处置（进 `01` 任务表 T-05）：
1. 给 `cover / statement / split / quote / closing` 补块级 `enter`（封面标题 `rise`、引语 `fade`、分栏要点 `rise` 错峰 60ms）；
2. 目标：**全盘覆盖 ≥ 60%**，且每幕至少 2 个块带 `enter`；
3. 造幕台保留一层**幕级入场**（整幕 `translateZ` 收束）作为兜底，用于 `enter` 为 0 的幕——这属于"容器动效"，不是伪造块动效。

### 7.4 耗时（只统计本地）

| 阶段 | 实测 |
|---|---|
| 单幕排版 + 溯源 + 过检 P50 | 0.95ms |
| 最慢一幕（`data`，21 块） | 2.85ms |
| 9 幕合计（不含网络/IO） | 5.18ms |
| 网络往返（12 次请求） | `待测`（真端点抓包回填） |

这条数据的意义：排版与过检**完全不是瓶颈**，造幕台可以放心在 `slide:layout` 后立刻起动画，不需要额外缓冲。

## 8. 离线复现（本次产出的第二个用途）

这次跑通的产物直接当 fixtures 用：

| 文件 | 用途 |
|---|---|
| `assets/trace-prompts.json` | 断言"prompt 未漂移"：`outlineRequest()` 输出与之逐字比对 |
| `assets/trace-model-responses.json` | `replay` 通道的录制源：按 `task + promptDigest` 命中，按 `chunks[]` 节奏吐字 |
| `assets/deck-trace.json` | 结构基线：任何一次回放产物必须与之**同构**（忽略 id 与时间戳） |
| `assets/assemble-manifest.json` | 装台动效基线：逐幕列出 `enter` / `enterDelayMs` / 包围盒，`04` 用它对拍 |
| `assets/trace-summary.json` | 指标基线：块数、字数、token、lint 结论 |

回放规则（与 `05` §11 一致）：

```
replay(provider).complete(req)
  ├─ key = taskOf(req.system) + ':' + shortHash(req.user)
  ├─ hit → 按 delays[] 逐 chunk 吐出（造幕台据此做逐字成幕）
  └─ miss → 抛 AiError('notConfigured', 'replay.miss')
```

e2e 断言（写进 `07`）：

1. 离线回放 → 9 幕；
2. `lintDeck` 0 error；
3. 块数 = 84 ± 0；
4. 装台清单里 `enter !== 'none'` 的块 ≥ 30（补完 T-05 后提到 ≥ 51）。

## 9. 这次跑通对造幕台意味着什么

把这些事件按 `02` §4.3 的 `ForgeStageEvent` 重放，用户会看到：

| 时间线（相对） | 事件 | 造幕台表现 |
|---|---|---|
| t0 | `composeOutline` 返回 | 起念 → 抽幕，9 张卡摊开 |
| t0+0ms | `slide:start ×2` | 两台位亮起 |
| 首个 token | `slide:content` 流式 | 标题逐字出现在在铸幕上 |
| 视觉阶段 | `slide:visual kind:'three'` | 台面右下角亮起粒子（L3） |
| 排版完成 | `slide:layout blocks:21` | 21 个块按 `enter` 错峰入场（该幕 8 个有动效） |
| 过检 | `slide:gate errors:[] warns:[]` | 两道门点亮金线，幕穿过落位 |
| 收尾 | `deck:done` | 完成栈排成一排，「播放」按钮取封面 accent 上色 |

一次真实跑通的产物 = 一次可回放的演示 = 一套 e2e 基线。这是本轮"接入自己"最实际的收益：**演示不依赖网络，回归不依赖运气**。

## 未决

1. 12 次请求里 SVG 与 three 是串在单幕里发的（`buildOneSlide` 内部），造幕台若想"先看到 9 幕文字、再补视觉"，需要在 `05` 里加一个 `visual: 'defer'` 模式——本期未做，列 v0.3。
2. 界面上的实时用量仍走代码里的 `len/4`（`provider.ts` 的 `estimateTokens`），与 §7.2 的 CJK 感知口径差 2.2 倍；要么统一口径，要么在 UI 上显式标"估算"，别让人拿它算钱。
3. `tooManyBlocks` 的"配方来源豁免"需要 lint 知道块是谁生成的——当前 `lintDeck` 拿不到 `provenance.recipeId` 的判定上下文，要在 `07` 里确认改动面。
4. 本次只跑了 `zh/normal`。`en/deep`（12 幕）与 `zh/short`（6 幕）待补 trace，否则 fixtures 覆盖不足。
