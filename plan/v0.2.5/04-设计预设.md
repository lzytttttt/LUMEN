## 1. 三个新字段（契约 §6.2）

```ts
// src/schema/deck.ts · themeSchema —— 只追加，不动任何既有字段
texture: z.object({ kind: z.enum(['none','grain','grid','scan','dots']), opacity: z.number().min(0).max(1) }).optional(),
glow: z.number().min(0).max(1).optional(),        // accent 光晕强度
elevation: z.enum(['flat','raised','layered']).optional(),
```

兼容性论证（不是"应该没问题"，是逐条可验证的）：

| 风险 | 事实 | 保护 |
|---|---|---|
| 旧工程文件反序列化 | `deckFileSchema.deck` 只存 `themeId` + `themeOverrides`，**从不存主题对象** | 新字段在主题侧，天然不进 Deck |
| 外部/旧主题对象解析 | 三个字段都是 `.optional()`，缺失即 `undefined` | `tests/unit/themes-v025.test.ts` §"旧主题对象照旧解析" |
| 旧主题的渲染结果 | 缺字段 → `texture: none` / `glow: 0` / `elevation: flat` | 断言变量等于 `none` / `0` / `flat` / 阴影 `none` |
| 旧 Deck 的导出 | 导出的变量表由 `themeCssVars()` 现算，缺字段就给默认值 | 断言旧主题的 `--d-texture-image` 是 `none` |
| 越界/未知值 | zod 直接拒（`glow: 1.2`、`elevation: 'high'`、`opacity: 2`） | 三条 `safeParse(...).success === false` |

## 2. 新增变量与 token 语义表

| 变量 | 语义 | 谁写 | 谁读 | 缺省/兜底 |
|---|---|---|---|---|
| `--d-texture` | 纹理**档位名**（`none`/`grain`/`grid`/`scan`/`dots`） | `themeCssVars` | 主题面板/诊断；`--d-texture-image` 的上游 | `none` |
| `--d-texture-op` | 纹理强度 0..1（`kind: none` 时强制 `0`） | `textureOpacityOf()` | `slide.css` `.lumen-slide::before` 的 `opacity` | `0` |
| `--d-texture-image` | 纹理**瓦片**（alpha data URI，mask 用） | `textureTileOf(kind)` | `slide.css` 的 `mask-image` / `-webkit-mask-image` | `none` |
| `--d-glow` | accent 光晕强度 0..1 | `themeCssVars` | `.lumen-slide::after` 的 `opacity` 与呼吸关键帧 | `0` |
| `--d-elevation` | 层次档位名（`flat`/`raised`/`layered`） | `themeCssVars` | 诊断；决定下面两个阴影的**取值** | `flat` |
| `--d-shadow-1` | 一档阴影（媒体框、占位、芯片） | `shadowsOf(elevation, bg)` | `.lumen-image` / `.lumen-html` / `.lumen-placeholder` | `none` |
| `--d-shadow-2` | 二档阴影（3D 焦点媒体） | `shadowsOf(elevation, bg)` | `.lumen-three` | `none` |
| `--d-surface-2` | 二级表面（媒体底、骨架、徽标、降级视图） | `surface2Of(bg, surface)` | `slide.css` 的 `color-mix(..., var(--d-surface-2) N%)` | 同 `surface` |
| `--d-accent-soft` | accent 的 12% 软底 | `accentSoftOf(accent)` | 光晕径向渐变、`.lumen-code` 底色 | `color-mix(in srgb, accent 12%, transparent)` |

**为什么是 9 个而不是契约的 8 个**：`--d-texture` 是关键字，CSS 没法用变量值去选图案（`background-image: var(--d-texture)` 是非法值）。要在不动渲染器（`SlideRenderer` / `BlockFrame` 不在本轮写作用域）的前提下让纹理真的出现，只有两条路：给 DOM 加 `data-texture`，或在变量表里多派生一个瓦片。选了后者：**一处生成、编辑器与导出同源、零 DOM 改动**。`--d-texture` 仍然如实输出，面板/诊断可读。

## 5. 纹理 / 光晕 / 层次的取值理由

| 主题 | 纹理 | glow | 层次 | 理由 |
|---|---|---|---|---|
| `noir` | `grain 0.07` | 0.45 | `layered` | 胶片颗粒压住深墨底的"塑料感"；金色光晕只在左上角起一层薄雾；双层阴影让 3D 媒体像贴在幕面上 |
| `paper` | `dots 0.05` | 0.18 | `raised` | 印刷网点是纸本最贴的老工艺；朱砂光晕几乎看不见，只做"油墨反光"；单层托起，避免纸片飘起来 |
| `aurora` | `grain 0.04` | 0.75 | `layered` | 极光要"空气感"：噪点像星尘，光晕最强（0.75）做极光本体；双层阴影给深空层次 |
| `signal` | `grid 0.05` | 0.08 | `flat` | 瑞士栅格就该有栅格；重体大字 + 平层，任何阴影都会破坏"印刷品"的观感，所以 `flat`（阴影全 `none`） |
| `museum` | `none 0` | 0.12 | `raised` | 美术馆的墙必须干净——**唯一刻意用 `none` 的一套**，证明"无纹理"也是明确立场；展签靠一层浅阴影离墙 |
| `terminal` | `scan 0.06` | 0.55 | `flat` | CRT 扫描线；荧光绿光晕给"屏幕在发亮"；终端界面不许有浮起感，`flat` |

强度标定方法：戴 100% 亮度在 1600×900 全屏看，纹理"能感到、读不出重复"，即 `grain ≤ 0.07`、`grid/scan/dots ≤ 0.06`；光晕以"能看出角落有染色，但正文对比度读数不掉"为上限（光晕层压在内容之下，且 `z-index: -1`，不叠字）。

### 5.1 accent / accent2 的使用规则（六套通用，写进令牌语义）

- `accent` 是**唯一主强调**：标题短横线、数据高亮的最后一根柱、焦点态、`strong` 之外的唯一着色文字。每幕最多出现 2 次。
- `accent2` 是**次强调/反衬**：图表第二序列、装饰圆点/圆环、可与 accent 组成双色渐变（SVG `lumen-g1`）。**不与 accent 同权重并列**，不用于正文。
- 两者都不做大面积底色：需要"面"时用 `--d-surface-2`，需要"软底"时用 `--d-accent-soft`（12%）。
- 对比度纪律：`accent on bg ≥ 3:1`；要落到正文/小字（< 18.66px 或 < 24px）时由 `recipes.ts` 的 `ink()` 按 `aaThreshold` 自动退回 `fg`——`signal` 的电红（4.13）就是靠这条守住可读性的。

### 5.2 圆角与动效曲线：逐套复核后**保持原值**

本轮不动 `radius` / `motion`：它们是六套的性格来源，且改动会牵动 3D 块圆角、转场手感与既有截图基线，收益（"换个圆角"）远小于噪声（全局视觉 diff）。复核结论：

| 主题 | radius | motion | 判定 |
|---|---|---|---|
| `noir` | 10 | 460ms · `cubic-bezier(.32,.72,0,1)` | 银幕质感，圆角 10 是"胶片框"的软硬分界，保持 |
| `paper` | 4 | 380ms · `cubic-bezier(.4,.14,.3,1)` | 纸边只有一点点倒角，4 是正确的；曲线收得快，像翻页 |
| `aurora` | 14 | 520ms · `cubic-bezier(.22,.9,.24,1)` | 流体/气体，圆角最大、时长最长，保持 |
| `signal` | 0 | 320ms · `cubic-bezier(.2,.8,.2,1)` | 直角 + 快切是瑞士印刷的底线，保持 |
| `museum` | 2 | 560ms · `cubic-bezier(.45,.1,.25,1)` | 展签几乎不圆，慢速"走进去"的观展节奏，保持 |
| `terminal` | 0 | 300ms · `steps(6, end)` | 直角 + 步进动画就是终端，保持 |

## 7. 导出一致性怎么证明

不是"看图觉得一样"，是四条可复现的断言 + 一次浏览器读数：

1. **同一函数**：`themeCssVars()` 是唯一入口；`themeVarsCss()` / `themeInlineStyle()` 只是它的两种序列化。测试断言 `themeInlineStyle(theme)` 里出现全部 9 个新变量名。
2. **同一段 CSS**：`buildStandaloneHtml()` 的 `themeCss` 就是 `themeVarsCss(themeCssVars(theme, deck.themeOverrides))`。测试用同样参数调 `composeStandaloneHtml()`，再从生成 HTML 的 `<style id="lumen-theme">` 里取回内联块，断言 9 个变量一个不少。
3. **同一份规则**：纹理/光晕/阴影的规则只有 `src/render/slide.css` 一份，播放器构建（`scripts/build-player.mjs`）把它打进 `public/player/lumen-player.css`，导出再整份内联。测试直接读该构建产物（存在时）：必须含 `--d-texture-image` 与 `lumen-glow-breathe`。
4. **打印不断层**：`PRINT_CSS` 的 `print-color-adjust: exact` 覆盖 `*::before/*::after`，纹理与阴影不会被浏览器省掉；测试断言该规则仍在。
