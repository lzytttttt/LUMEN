## 4.2 本轮修掉的既有缺陷（v0.2.0 起就有，不是新增回归）

| # | 缺陷 | 根因 | 修法 | 钉它的用例 |
|---|---|---|---|---|
| B-1 | **加幕后再生成必崩**：`cast` 抛非 `AiError`，台面显示「网络断了」 | `state.add` 只往卡片数组插一项，`outline.slides` 不跟着长；`syncOutline` 在「卡片数 > 大纲项数」时展开 `undefined`，产出只有 `{recipe, headline}` 的残缺 `OutlineSlide`，生成期 `visualOf()` 读 `slide.visual.kind` 抛 `TypeError` | ① `add` 同步往 `outline.slides` 插入完整 `OutlineSlide`（`statement` + `points: []` + `visual: none`），位置与卡片一致；② `syncOutline` 用 `blankOutlineSlide()` 兜底，任何"卡片比大纲多"的 state 都不再产出残缺项 | `tests/unit/forge-flow-v025.test.ts`：纯 reducer 断言 12 幕逐项字段 + `outlineSchema.safeParse` 通过；真实路径 `composeOutline → add×3 → cast → buildDeckFromOutline` 出 12 幕且每幕有块 |

> 意义：v0.2.0 的 `add` 三条用例只断言了长度与首末锁，**没断言大纲项完整性**；v0.2.5 的「再加几幕」把它从"偶尔"变成"必现"。
> 由此，`05` 原先隐含的「add 之后不要 cast」前提**作废**——现在允许加幕再生成。

## 5. 视觉基线怎么复核（人判，写清判据）

| 屏 | 判据（三选二即算过） |
|---|---|
| 起念 | 材料/受众/预设入口不抢输入行的视觉重心；仍只有一个聚焦点；小字不超 11px |
| 大纲 | 卡内编辑态不破坏 4×3 / 5×4 栅格；锁卡仍不可删；焦点环可见 |
| 生成 | 冲击波只出现在刚落位的那一叠；栈深度不遮挡当前幕；环形进度在 200ms 内可读 |
| 过检 | 火花不糊住错误文案；红/黄语义仍靠 `data-severity` 而非颜色本身 |
| 开演 | 弧线仍居中；三枚下一步不压暗角；扫光不扫过按钮 |

复核方式：`?still=1` 出静态基线，L1/L2/L3 各出一张动态首帧，与 `plan/v0.2.0/assets/forge-0*.png` 并排看结构是否漂移。

## 6. CI 顺序（本地等价）

```powershell
node node_modules/typescript/bin/tsc --noEmit
node node_modules/vitest/vitest.mjs run
pnpm build
pnpm e2e -- forge-flow
```

四条全绿才允许进 M4 发版；`pnpm build` 与 `pnpm e2e` 之间不要 `git clean`（player 预构建产物被 e2e 复用）。
