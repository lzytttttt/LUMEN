## 3. 并行与依赖

```
M0 契约冻结（lead）
   ├── flow-state  T-25-01…05 的类型与 reducer   ← 最先落地，其余人靠它编译
   │      └── flow-ui   T-25-01…05 的界面与文案  ← 结构可先写，编译等类型
   ├── fx-artist   T-25-06 视效                  ← 不依赖状态层，立即开工
   └── themes      T-25-07 预设                  ← 不依赖状态层，立即开工
M3 整合（lead）→ M4 发版
```

**并发纪律**（`02` §7 的落地版）：

1. 一个文件只有一个 owner；跨 owner 的改动走消息协商，不直接落笔。
2. `src/forge/forge.css`（fx-artist）与 `src/forge/flow.css`（flow-ui）**物理隔离**：新结构只准进 `flow.css`。
3. `src/schema/deck.ts` 被两个 owner 切块：`outlineSlideSchema.brief` 归 flow-state，`themeSchema.{texture,glow,elevation}` 归 themes；各自只准加自己的字段。
4. 谁把自己的工作流跑红（`tsc` 或既有用例），谁先修好再继续，不把红留给整合。
